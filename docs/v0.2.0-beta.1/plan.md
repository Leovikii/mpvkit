## 1. 窗口和两页结构

默认窗口 **560×760**，最小内容 **480×600**（CSS 逻辑像素，本机 GTK/WebKit 已复核）。移除侧栏和图标导航栏，两页占用同一个内容面，不增加路由依赖。内容纵向滚动，主操作区固定在底部，长文和 200% 字号允许控件换行。

| 页面 | 内容 | 入口与操作 |
| --- | --- | --- |
| 配置，默认首页 | 画质、HDR、自动连播、播放结束行为；播放增强作为一组状态；高级项收纳实际目录、组件版本及来源 | 右上角设置图标按钮；右下角一键安装或一键卸载；有草稿时提供保存配置 |
| 设置 | 语言/主题；MPV 核心区域；MpvKit 自身更新；打开日志文件夹；仓库链接 | 左上角返回配置；不增加页面级刷新按钮，不再设独立核心页或关于页 |

- MPV 单独为一个简短区域：名称、版本、状态、WinGet / Pacman 来源，缺失时一个安装按钮，已安装时一个管理菜单收纳更新、默认应用和独立核心卸载。避免与应用自身版本、更新混在同一行。
- 关于区域仅保留一个 **GitHub 图标 + Leovikii** 的简单次要按钮，点击使用系统浏览器打开固定仓库 `https://github.com/Leovikii/mpvkit`。移除“Repository / 仓库”标题行和裸露网址，不再摆放品牌大卡片、重复简介或仓库列表；图标使用本地单色 SVG，不为此新增图标库或远程加载资源。按钮有可访问名称“在 GitHub 查看 MpvKit 仓库”，署名在双语界面均保持 Leovikii。
- **删除整行版权许可证界面**，包括“Copyright & license / 版权与许可”标题、GPL-3.0-or-later 文字及 Copyright & license、Third-party notices 两个按钮，不留空容器或分隔线。应用版本作为应用更新行的辅助文字；已有许可材料继续随包提供，保持分发和声明检查，不因简化关于界面删除许可文件。
- 删除高级区的诊断导出路径输入、预览及导出按钮，改成一个普通的“打开日志文件夹 / Open logs folder”按钮，不为单个按钮保留空的高级折叠区。日志自动留在本机，不要求用户手填文件路径。
- 语言和主题默认跟随系统，偏好即时生效；配置草稿切页保留。设置页返回后恢复配置页，应用每次正常启动默认显示配置页。
- 配置页始终可进入，允许安装前编辑本次设置，也允许核心缺失时清理已有配置。不再要求增强已安装才允许进入其自身安装页面。
- 页头不重复放刷新，启动、返回应用及任务完成后只读检测；加载失败就地提供重试。应用更新的检查按钮仍保留，作用与播放器状态检测分开。
- 保留现有 `fade-up` 200 ms / ease-out、Modal fade 160/120 ms、Accordion 180 ms、Tooltip 120/90 ms；尊重减少动态效果，不因移除侧栏改用横向滑动或新增动效库。设置和返回入口均有可访问名称及回焦目标。

### 系统窗口装饰（2026-10-31 反馈）

用户指出 GTK 标题栏与 KDE 装饰和阴影不同。Linux 已删除自建 HeaderBar 和标题栏样式，使用 KWin 服务端装饰，遵循当前系统的标题栏、按钮位置、边框和阴影。保留应用内容区材质；应用内主题不强制改变系统标题栏。此决定覆盖旧版统一标题栏染色要求，不修改 KDE 全局配置。独立 ELF 没有安装 desktop/icon 资产，系统装饰可能显示默认 Wayland 图标；正式包图标仍需隔离安装验收。

### 内容区去除套层（2026-10-31 反馈）

针对窗口“里一层外一层”的反馈，两页改为铺满客户区，删除外围 8px 留白、描边、大圆角及独立底色；只保留统一窗口基底和设置分组。底部固定操作区沿用页面背景，高级选项移除与卡片重复的顶部边线。KWin 系统标题栏、边框和阴影保持。产品和离线预览已同步，浅深主题、双语、480/560/720 宽、200% 文字及真实 GTK/WebKit 回归通过。

### 操作对齐（2026-10-31 反馈）

两页共用一套设置行：说明、版本和状态在左，控件在右；空间不足自然换行，控件仍保持右边缘，不把开关整行拉伸。移除更新区特殊布局与窄屏强制纵排，MPV 管理区只在右侧放一个动作。主页底部主要动作位于组内最右，修复/卸载为次要动作；日志/GitHub 和高级项操作成组靠右。按钮长文本允许换行，不截断。弹窗保持现有确认/取消顺序。

离线实际 App 增加两页控件实际右边缘检查和设置页截图，覆盖480/560/720、双语、浅深色、200%文字；原生验收保留两页浅深截图，不再只检查主页。

## 2. 安装状态与主操作

增强与配置共同部署到当前解析出的 MPV 原生配置根，不引入另一个自定义管理目录，不保留逐组件安装按钮。

| 实际状态 | 配置页操作 |
| --- | --- |
| 未安装整套播放配置 | 右下角“一键安装”，使用当前表单设置 |
| 已安装且无草稿 | 右下角“一键卸载”；普通危险操作样式，不默认聚焦执行 |
| 已安装且有草稿 | “保存配置”为主要动作，旁边保留“一键卸载”；保存不重复下载或重装健康组件 |
| 部分缺失/损坏或上次部署中断 | 如实显示状态，就地提供统一修复/恢复；仍允许完整卸载，不能仅凭目录存在认定安装完成 |
| 目录只有原有用户配置、没有本程序安装记录 | 继续显示安装入口；预览显示现有内容与冲突，不把任意已有 MPV 目录当成已完成的 MpvKit 安装 |

健康项跳过；不能把“保存配置”实现成整套重装。重置配置仍是低频操作，置于高级项，并保留明确的覆盖后果。正常安装/保存继续保护手改和未知文件；只有用户主动确认的完整卸载才删除整个根。

## 3. 一键安装：一次应用确认，同窗完成

1. 点击“一键安装”后打开一个任务 Modal，先只读检查核心、配置路径和安装状态。准备期间不写目标配置目录。
2. 同一弹窗呈现简短安装摘要、实际配置目录及必要冲突。核心缺失时明确提示：**“未找到 MPV，将先安装 MPV，再安装播放配置。”** 提供“安装 / 取消”，用户只做一次 MpvKit 确认，不另开核心确认弹窗或跳设置页。
3. 用户确认后，若缺核心则先发起原生 WinGet / Pacman 安装；原生包管理器、安装器和 UAC / Polkit 的询问由用户自行回答。应用弹窗显示“等待包管理器”并保留任务状态。
4. 等核心命令真实结束，重新检测实际核心路径、版本与所需能力，并再次核对配置目标。只有命令成功、核心可用且目标未发生未经确认的变化，才继续下载/校验所需增强、生成配置和运行桥接，然后部署到已确认的配置根；原本已有可用核心则跳过核心安装阶段。
5. 部署使用现有归属、摘要、互斥、过期计划复核及当前操作失败恢复。确认后的核心或目录变化不能继续覆盖；同窗说明原因，重新准备作为新的重试，不静默改目标。
6. 成功或失败留在同一 Modal。核心安装失败/取消时停止后续部署，即使复核发现核心已出现，也分别报告原始结果与检测状态，不静默继续；重试重新准备并可跳过已可用核心。核心已装但配置失败时显示“MPV 已安装；播放配置安装失败”，重试只准备尚未完成内容，不卸载已安装的核心。

一次应用确认不等于禁止原生询问：保留原生终端/安装器输入与系统授权，不添加 `--noconfirm`、自动接受协议、强制静默或禁止交互参数。应用同窗承载编排、短阶段、结果与详情；原生问题仍由原生界面承载，不自制终端模拟器或代用户回答。

## 4. 一键卸载：完整目录删除，可选核心卸载

点击“一键卸载”后，在一个 Modal 中显示：

- 实际配置根路径。
- 极简后果说明：**“将删除此 MPV 配置目录及全部内容，包括其他脚本、手改配置和续播记录。”**
- 核心存在时提供 **“同时卸载 MPV”** 复选框，建议默认不勾选。选择值必须明确传给后端，不从“是否由本程序首次安装”猜测当前系统核心是否可以删除；其他软件也可能依赖它。
- 按钮为“卸载 / 取消”，默认聚焦取消。此处完成一次应用确认，不再弹出独立的核心确认或目录删除确认。

执行规则：

1. 未选择卸载核心：直接执行已确认的完整配置目录删除。
2. 选择卸载核心：先发起固定目标的包管理器卸载，保留其原始询问、依赖处理、授权及退出结果；随后执行已确认的完整配置目录删除。**包管理器失败、依赖拒绝、取消或无法启动，不阻断配置清理。** 两步是用户确认的独立操作，不伪装成跨包管理器与文件系统的原子事务。
3. 不自动追加递归/级联卸载、清除配置、强制忽略依赖或重试命令。Pacman `-R mpv` 可能直接拒绝被依赖的核心；原样报告即可。
4. 完整删除范围是本次已解析并展示的 MPV 配置根及其全部子内容；包含增强、conf、profiles、脚本选项、运行桥接、管理记录、手改、其他脚本及续播。用户已明确授权该产品功能覆盖旧版仅删自有未改文件的卸载约束。
5. 不追加清理应用偏好、其他用户目录、其他 MPV 根、系统 MPV 目录、包管理器缓存或宿主系统资产。开发验证仍用新隔离根，本决定不授权直接删除开发者真实配置。

删除目标固定为本次确认展示的根；核心卸载后即使原生路径解析改变，也不转而删除新目录。原目标已被包管理器移除时记为已清理，仍需核对路径身份，不能以同名新建目录替代已确认目标。

同窗分别报告两步结果，例如：

| 核心结果 | 目录结果 | 界面反馈 |
| --- | --- | --- |
| 未请求卸载 | 已删除 | 配置已删除；MPV 保留 |
| 卸载成功且复核已移除 | 已删除 | MPV 和配置已卸载 |
| 卸载失败/取消/仍存在 | 已删除 | 配置已删除；MPV 卸载未完成，详情显示原始结果 |
| 卸载成功 | 删除失败/部分完成 | MPV 已卸载；配置清理未完成，列出剩余目标及原因 |
| 卸载失败 | 删除失败/部分完成 | 分别显示包管理器与目录清理错误，不合并为笼统成功 |

重试只处理失败阶段：目录已删后不再要求目录存在才能报告核心错误；核心已卸载后不重复发起卸载。不能为了整齐的“成功/失败”文案隐去部分结果。

## 5. 任务反馈和原生执行边界

- 确认、执行、结果和重试使用同一个 Modal；下载/部署/删除与包管理器任务执行中保留当前任务，不因为切页、焦点变化或晚到事件重复运行。
- 已知总量的文件下载使用 Mantine Progress；包管理器授权、依赖处理和原生安装没有可靠总量时，只显示 Loader 与一行阶段文字。必要输出按需展开并限制内存体积，不从本地化输出猜百分比；弹窗输出不等于将完整原始输出持久写入日志。
- 必须取得**包管理器实际退出码**与必要原始输出。启动终端成功、终端窗口关闭、Konsole 进程退出都不能替代包管理器结果；执行入口需要可等待的真实命令结果，不能沿用当前只 `spawn` 后立刻返回的中间实现。若需薄层原生命令 helper，只服务于当前任务的交互和结果回传，不引入常驻服务、通用命令执行接口或任意 shell 输入。
- 命令固定 Windows `shinchiro.mpv` / winget 源、Linux Pacman `mpv`，独立传参。不自动刷新数据库或执行整机升级。包管理器持锁/依赖/网络问题由其自身处理，MpvKit 只报告。
- 命令结束后只读复核状态，真实退出码和实测状态不一致时分别呈现，不把“已启动”写成“已安装/已卸载”。密码、用户输入和凭据不进入任务日志。
- 包管理器事务进行中不提供会强杀事务的应用取消；提交前可取消准备，失败或完成后可关闭。任务运行中防止重复提交及应用更新重启，保持原生进程控制权。

## 6. 目录删除与数据一致性

- 沿用原生配置路径解析，拒绝相对/歧义目标；预览列出实际根及将删除内容，运行前重新核对根与内容。完整删除还须拒绝文件系统根、用户主目录、应用数据根和系统目录等非专用 MPV 配置目标，不能因 MPV_HOME 指向它们就递归删除。路径和计划过期后重新准备，不能按目录名猜测删除目标。
- 符号链接与 Windows 重解析点不跟随到目录外；不通过放宽路径校验实现“完全删除”。
- 配置写入、完整删除和播放期 helper 共用配置根外的稳定锁，完整删除不会删除正在持有的锁，避免两个进程各持不同锁。
- 删除失败必须保留可诊断的真实状态，报告剩余路径；“全部内容删除”不建立历史备份或承诺可撤销。新建文件、被占用文件、权限错误及中途退出都要测试，不能仅验证空目录路径。
- 配置安装失败继续使用当前事务恢复；完整目录删除与系统包事务不能承诺彼此回滚。核心安装/卸载状态不写入配置文件所有权清单，不复制系统核心。

## 7. 语言、图标、应用更新与简化建议

### 必须处理的已有反馈

- **系统语言**：前后端默认均应为 system。旧测试启动脚本预写 zh-Hans/light，隔离 `XDG_CONFIG_HOME` 又使 `kreadconfig6` 读不到真实 KDE 偏好；新测试入口保留生产默认、正确读取系统偏好，同时继续隔离应用写入。不能靠强制中文冒充跟随系统通过。
- **Wayland 图标**：app_id、包内 desktop 和 Icon 名保持 `io.github.mpvkit`。本机管理器已卸载、独立 ELF 缺少已安装桌面资产，app_id 正确不能证明系统装饰与任务栏图标关联通过；需在具备包资产的隔离 KDE 安装环境验证任务栏/切换器图标，不向宿主临时注册桌面资产伪造结果。
- **应用更新自动重启**：Windows 使用官方 updater 的重启参数和 NSIS 成功回调；Linux 安装后核对包身份/版本、释放操作锁后用 Tauri 重启。只在更新成功后重启，失败/取消留在同窗；有草稿或 MPV 任务运行时不能启动更新安装。

### 本地日志替代手动诊断导出

现有诊断导出生成一次性的 JSON 状态快照，包括应用/组件版本、核心问题代码、配置是否修改及管理文件计数；不包含历史失败过程或原始日志。用户明确要求删除此功能，改为自动记录问题并打开日志目录。以下为 beta.1 已实现的边界，实际验证和限制见末节。

- **入口与存储**：设置页仅保留“打开日志文件夹”，通过原生文件管理器打开 Tauri 平台标准应用日志目录；目录缺失时按需创建，创建/打开失败就地提示。目录独立于 MPV 配置根，完整卸载配置后仍能排查失败。不增加路径选择、日志等级、导出/上传、手动清理或实时日志查看器。
- **记录内容**：保存应用版本、系统/架构、时间、任务编号、操作/阶段、耗时、结果、错误代码、必要的系统错误码及包管理器真实退出码。安装、保存、卸载、恢复和应用更新记录简短的开始/关键阶段/结束摘要；下载、校验、权限、路径冲突、删除及前端未处理异常保留经过脱敏的失败信息。用户取消标为取消，核心与配置的部分完成分别记录，不合并成成功。只对可捕获的异常尽力记录，不承诺强制结束、断电或原生崩溃必有末条日志。
- **容量与清理**：采用 UTF-8 文本，每条最多 **8 KiB**，单文件最多 **1 MiB**，只保留当前文件和 **3 个轮转文件**，总量最多 **4 MiB**。写入前按完整记录长度核对并轮转，不能先任意写大再清理；超长记录截断并标记。超过 **7 天**的本程序日志在下次启动或写入轮转时清理，应用关闭期间不运行清理任务。仅操作固定命名的自有日志，不递归扫描、不跟随链接/重解析点，不删其他文件或系统日志。
- **性能与失败处理**：只记录任务边界、必要警告和失败；不记录下载进度刻度、轮询、鼠标/键盘、每次渲染或播放进度。同一后台检测问题持续存在时只记首次，恢复后记一次恢复；再次出现再记录。日志 I/O 与小范围轮转放在工作线程，保持记录及待写数据有界，不在 UI 线程扫描或同步刷盘，不逐条 fsync；不增加定时扫描、常驻服务或通用日志框架。写入失败/磁盘满不能阻止主操作、覆盖其原始错误或递归记录日志错误；会话内停止重复写入尝试，日志入口就地显示不可用状态。多个进程/helper 写入及跨重启轮转需保证互斥和上述容量边界。
- **本地与隐私**：默认不上传；不记录密码、用户输入、媒体文件名/路径、原始配置、环境变量全集或带凭据 URL。使用已知字段白名单和脱敏后的错误摘要，不直接序列化完整错误对象、任意 JS 异常或原样复制终端输出；目录用配置根等标识代替用户名及绝对路径。日志采用当前用户权限。弹窗仍显示用户完成操作所需的真实目标与结果，不以日志代替当场反馈。
- **删除旧功能的范围**：同步移除前端导出状态/文案、IPC 注册、PendingExport、专用诊断导出模块与其不再适用的测试及预览夹具；保留仍被其他功能使用的检测逻辑。新增的验证集中于记录、脱敏、限额、轮转、清理、并发及失败降级，不保留两套入口。普通测试使用隔离日志根，不读写或清理宿主日志。

### 建议采用的交互细节

- MPV 管理使用设置页中的独立小区域；关于只保留仓库按钮，避免用户把 MPV 更新与 MpvKit 更新混淆。
- “同时卸载 MPV”默认不选；完整配置删除作为一键卸载的固定含义，简短说明不能省去实际路径及全部内容删除后果。
- 已安装时保留明确的“保存配置”，正常保存不重装健康内容；无改动时不展示重复的保存按钮或保持其禁用，实施时选择一种一致方式。
- 任务按阶段分别报告结果。原生核心卸载失败不阻挡用户已确认的配置清理，配置删除失败也不抹掉包管理器的真实结果。
