# MpvKit 界面开发规范

更新：2026-11-02；本轮补查按钮、图标、菜单与开关的官方依据，见 [beta.2 组件审查](../v0.2.0-beta.2/plan.md#管理器组件审查)，其余官方依据上次核对为 2026-10-28。管理器界面按 [beta.1 方案](../v0.2.0-beta.1/plan.md)保持窄窗配置/设置两页、无侧栏及现有动效；播放控件新增 [beta.2 原生配置约束](../v0.2.0-beta.2/plan.md#uosc-原生配置)，已在 beta.2 实施。两页及统一安装/完整卸载继续保留，本版验收见 beta.2 交接；已发布三页事实见 [开发基线](../current.md)与[alpha.5 交接](../v0.2.0-alpha.5/plan.md)。v0.1.5 仅为历史设计依据。

## MPV 播放控件与 uosc

beta.3 界面要求见 [本版方案](../v0.2.0-beta.3/plan.md)：主播放配置只保留默认画质，删除 HDR、自动连播及结束行为控件；三项使用默认值并收入 uosc 菜单。必要维护入口及设置页继续保留，不以默认值摘要填补已删除控件的空间。

安装和完整重新应用按管理器当前实际语言生成单语言菜单、控件提示和自有提示；uosc 内置语言同步，切换管理器语言不自动重写播放器配置。菜单文本必须简洁精确，使用短名词/动词，不拼接双语、不写教程、技术参数或冗长解释；目标文案见 [菜单文案](../v0.2.0-beta.3/plan.md#菜单文案)。必要风险在对应确认或失败提示中说明，不以精简为由删除。

播放控件遵循最小开发成本：仅通过固定 uosc 上游公开的原生配置调整图标排列、分组、全局尺寸与留白，通过公开菜单接口打开功能。尽量保留现有布局和可配置尺寸；原生能力不足时简化要求，不追求旧视觉的逐像素复刻。

禁止为布局/外观追加或注入 Lua、包装内部方法、依赖内部对象、修改上游源码或维护 fork；不新增自绘控件、通用布局系统或样式切换。uosc Lua 保持固定上游原文字节，旧版“原始前缀加 bridge”不符合此要求。自有画质/保存/窗口修复业务不受删外观代码影响，调用 uosc 时只使用公开接口。

当前目标为左三控/右功能组、底部独立原生进度条，统一按钮尺寸；发布后 dev 调整为右侧播放列表、字幕、音轨、更多、全屏；音轨在存在一条音轨时也展示，倍速仅收入更多菜单的固定档位子菜单，不自绘动态倍速文字。具体参数、升级与验证范围统一见 [beta.2 方案](../v0.2.0-beta.2/plan.md)。达到原生配置可实现的目标后即停止扩展；升级继续核对公开接口并定向验证，不承诺未来上游永久兼容。

## 依据与适用范围

采用微软 Windows 应用设计指导中的 WinUI 3 / Fluent 原则，以 Mantine 实现。不是将 WebView 改成 XAML，也不承诺像素级复制原生控件。以下是官方指导的项目化摘要，具体尺寸决策在下一节明确区分。

| 官方来源 | 采用的原则 |
| --- | --- |
| [NavigationView](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview) | 导航入口稳定，窄窗减少导航占用。beta.1 只保留默认配置页与设置入口，不使用 NavigationView 侧栏；这是项目取舍，不称为微软强制要求。 |
| [App settings](https://learn.microsoft.com/en-us/windows/apps/design/app-settings/guidelines-for-app-settings) | 设置是完整页面，相关项成组，说明在左、控件在右，内容限宽，偏好修改即时反馈。右上角设置与页内返回是本项目选择。SettingsCard 来自 Windows Community Toolkit，不是 Mantine 或 WinUI 内置控件。 |
| [Content layout and spacing](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics) | 用一致的留白表达分组；按钮间距 8 epx，表面内边距参考 16 epx；正文和分组标题建立层次。 |
| [Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography) | 正文常规字重、标题半粗、默认左对齐；使用系统字体和清晰字号层级。 |
| [Geometry](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/geometry) | 常驻控件圆角 4 px、弹层 8 px；相接边不重复圆角。 |
| [Mica](https://learn.microsoft.com/en-us/windows/apps/design/style/mica) | 材质用于窗口基底；内容层在基底之上。按系统能力、透明效果、节能和高对比策略回退，不能让每张卡片各自模糊。 |
| [Dialog controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/dialogs) | 标题直接说明任务、内容简短、按钮用明确动词；执行按钮在左，安全关闭在右；局部错误就地展示。 |
| [Progress controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/progress-controls) | 已知工作总量时显示确定进度，未知时用不确定指示及状态文字；下载完成不代表安装完成，不能伪造百分比。 |

不采用 Windows 7 旧版 UX 指导或 UWP 手机白皮书覆盖上述当前 Windows 页面。Microsoft Learn 页面会更新，后续修改应复核原文。

## 项目尺寸与视觉基线

下列是 MpvKit 的 CSS 逻辑像素选择，不是微软硬性指标。浏览器缩放/DPI 下使用 rem 和响应式布局；不按设备物理像素猜窗口大小。

| 项目 | 基线 |
| --- | --- |
| 窗口与导航 | 默认 560×760、最小 480×600，双端配置保持一致。无侧栏或图标导航栏；配置页右上角设置按钮，设置页左上角返回，均有可访问名称与键盘提示。 |
| 内容 | 左对齐；正常内边距 24，窄窗 16；两页铺满客户区，共用单一背景，无外围留白/描边/大圆角底板，独立纵向滚动；配置页底部主操作区固定，不遮挡末行。 |
| 留白 | 4 / 8 / 12 / 16 / 24 / 32；同类控件用同一组值，不逐页猜间距。 |
| 字体 | Segoe UI Variable → Segoe UI → Microsoft YaHei UI → sans-serif；页标题 28/600、分组标题 14/600、正文 14/400、辅助信息 12/400。 |
| 控件 | 选择/图标控件约 32，文字按钮使用 Mantine sm 的 36px 最小高度，信息行最小 64；文字增长时允许增高、换行，不裁切。设置和返回图标保留 Mantine 正常命中区及 Tooltip；不为窄窗压缩控件。 |
| 圆角 | 按钮/输入/分组 4，对话框 8；页面外围不加圆角。 |
| 表面 | 客户区使用统一窗口基底，不在其中另套有底色的整页容器；设置分组仅保留一层轻边框。底部操作区沿用页面背景；常驻内容无阴影，弹窗保留组件阴影；不用渐变横幅、玻璃卡片和大面积强调色。 |
| 颜色 | 中性色为主；强调色只用于主要动作、选中状态和焦点。状态必须有文本，不能只靠红绿。界面强调色固定为图标同源的 #A84BD6 紫色，使用一套 Mantine 色阶提供悬停与文字层次；不提供颜色选择或系统强调色跟随。图标继续复用现有 MPV SVG/PNG/ICO。 |

预览用纯色模拟窗口基底；浏览器无法验证真实 Mica。Windows 保留 DWM 标题栏与 Mica。Linux 使用 KWin 服务端窗口装饰（SSD），标题栏、按钮布局、边框和窗口阴影遵循用户 KDE 设置；不创建 GTK HeaderBar，不给系统装饰覆盖配色、高度或阴影。此决定覆盖 alpha.5 标题栏与内容区统一染色的旧要求。应用内浅深主题仅改变内容区，不能强制系统标题栏同步。

Linux 内容区仍通过标准 Wayland 背景效果能力决定模糊，高对比或无能力时回退为实色；WebView 单独透明，不清空 GTK 窗口基底。不增加材质开关。KDE 桌面入口、Icon 名称与 Wayland app_id 统一为 io.github.mpvkit，由 Arch 包安装。标题栏是否显示图标及图标位置由系统装饰决定；独立 ELF 未安装桌面资产时可能出现默认 Wayland 图标，不为预览向真实用户目录注册资产。

原生验收核对服务端装饰协商、用户主题的按钮/边框/阴影及内容区可读性，不再要求系统标题栏与内容区同色。默认与最小尺寸指内容区，外框随系统装饰变化。

## 组件复用与页面结构

Mantine core/hooks 继续固定 9.7.3。按 [官方快照](../vendor/mantine/README.md) 阅读实际组件正文，并核对本地声明。优先用组件 props、主题及公开 Styles API；不依赖内部哈希类名，不手写焦点锁、下拉菜单、复选框或折叠动画。

图标使用现有本地 SVG，显式设置尺寸并跟随 currentColor；装饰图标设 aria-hidden，控件保留可访问名称。按钮图标使用公开 leftSection/rightSection，纯图标操作优先 ActionIcon；不使用字体字符模拟箭头，再靠 top/translateY 修正视觉位置。保留组件命中区、键盘和焦点行为，不为窄窗压缩。共享按钮高度/换行样式仅按实测问题调整，不新增图标依赖或自制菜单。

文字按钮通过公开 root/inner/label 样式统一处理自动高度：保留 `--button-height` 最小高度，inner/label 为 auto，label 行高 1.5、text-box-trim=none，允许换行。不要在自动高度按钮中沿用 cap/alphabetic 裁剪加 overflow=hidden 的短标签盒，避免截掉英文 g/p/y 下伸部分或中文字边。中英文均实测完整 DOM 文字范围包含在标签区域内，文字离按钮四边至少 4px，标签及图标垂直居中；4px 是本项目的最低回归阈值，**不是微软规定的按钮内边距**。实际普通字号上下留白约 8px，水平沿用 Mantine sm；不靠逐字偏移、单独垫高英文或缩小中文解决。按 480/560/720、深浅主题、100%/200% 文字复验，结合截图检查视觉效果；几何测量不能替代读屏/字体渲染的真实设备验收。

| 用途 | 使用现有组件 |
| --- | --- |
| 窗口内布局、设置与返回 | 复用现有窗口壳及 Group / Stack；ActionIcon + Tooltip 使用 button 语义与可访问名称，无需引入路由库或新的导航组件 |
| 分组及设置行 | Paper + Group / Stack；只复用一种简单行布局，不做通用配置表单引擎 |
| 高级项、来源 | Accordion，设置正确 heading order；Control 内不嵌套按钮/输入 |
| 参数 | NativeSelect、TextInput、Checkbox；需确认的系统变更不能伪装成即时生效 Switch |
| 提示、进度 | Alert、Progress 或现有原生 progress；错误在相关区域，完成提示 aria-live=polite |
| 确认 | Modal；保留 trapFocus、returnFocus、Esc、可访问标题；执行中关闭规则沿用业务约束 |
| 滚动 | 两页用 ScrollArea，任务/更新弹窗用 ScrollArea.Autosize；复用组件滚轮、触摸、滑块拖动与键盘行为，不自绘滚动逻辑 |
| MPV 管理 | Menu 收纳更新、默认应用与独立核心卸载；保留键盘、焦点与危险项语义，不手写弹出菜单 |

beta.1 采用两页：**配置 / Configuration** 为默认页，合并播放选项、增强状态及统一安装/卸载；**设置 / Settings** 包含语言/主题、MPV 核心管理、MpvKit 更新、打开日志文件夹及仓库按钮。每次启动默认配置页；安装前可编辑，不设配置导航门禁。切页保留草稿。原侧栏、播放器独立页面及逐组件按钮移除，现有三页仅保留为 alpha.5 历史事实。

页面只设一个 h1。页头保留设置或返回入口，不增加常驻刷新按钮；启动、回到应用及任务完成后只读检测，检测失败就地重试。主要按钮放在对应任务附近。不要在每张卡片重复标题、状态和一组相同按钮。每个任务区域只有一个强调动作，正常状态用普通文字而非一排彩色徽章。

相关信息合并为行：名称、版本与状态说明在左，控件/操作在右。两页共用同一设置行布局；空间不足才换行，换行后的控件仍靠右，不为更新或 MPV 单独设置另一套断点。开关不拉伸到整行，选择框保持一致宽度并受可用空间限制。主页底部主要操作位于动作组最右，低频页内按钮及设置页日志/GitHub 按钮成组靠右，与设置行控件对齐；弹窗继续采用既有主要动作在前、安全关闭在后的顺序。完整路径可折行；目录入口收入对应高级项，实际路径配“打开”按钮，核心与配置使用一致布局。正常页不直接展示 JSON、哈希、来源 URL 列表或完整配置。相关详情折叠，不能删除审计信息。

默认推荐足够使用。beta.3 主配置区只展示画质选择，安装前可设置默认档位；HDR、自动连播、播放结束行为收入 uosc 菜单，不在 GUI 或高级项重复提供控件。“播放增强”直接列出 uosc、thumbfast、字幕字体；每行展示名称、简短用途、已安装版本和独立状态（未安装/已就绪/需要修复），不逐项设置安装按钮。thumbfast 提交号简写七位，完整来源仍在高级项。高级选项默认关闭，只保留目录、来源及安装后的重新应用配置，删除重复组件明细折叠。不展示无设置项的快捷键帮助，不提供管理器内打开媒体入口。危险操作必须有文字标题及确认；当前冲突、失败、恢复要求必须浮出高级区，不能藏在折叠内容里。

beta.3 实测后按设置页规范校正层级：“播放增强”标题置于卡片上方，14px/600，标题与列表间隔 8px，前组间隔 24px；行名称为 14px/400，用途及版本为 12px/400，状态右对齐。复用统一行高和 16px 内边距，分隔线沿用设置行的低对比颜色，不在首行前增加标题分隔线。页面与底栏统一水平边距，常规 24px、宽度不超过 520px 时 16px；这些具体尺寸为项目实现选择，依据为上表微软分组、层级与间距原则，不称为官方强制像素值。

即时保存的“包含预览版更新”继续用 Switch。选择框和需要的复选框通过 aria-labelledby 或组件 label 关联可见标题，不另封装表单。beta.2 自动连播 Checkbox 为已移除的历史界面，原依据见 [组件审查](../v0.2.0-beta.2/plan.md#组件取舍)。

溢出采用 Mantine [ScrollArea 官方正文](../vendor/mantine/core-scroll-area.md)及微软 [Scroll viewer controls](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/scroll-controls)的纵向优先、避免遮挡内容原则。两页和任务/更新弹窗统一 8px 滚动轨道与中性色圆角滑块，type=auto 仅溢出时显示，悬停加深；沿用内容边距为滑块留空，不使用宽大浏览器默认滚动条。滚动 viewport 可键盘聚焦并有可访问名称，高对比滑块使用系统 ButtonText。长配置/日志/更新说明自动折行，随所在弹窗整体滚动，不再嵌套限高 pre；底部操作固定，仍能到达末行。无需逐像素仿制 WinUI 动态缩窄动画。

弹窗最大高度沿用 Mantine 基于 yOffset 的原生计算，不能再写独立的 `100dvh - 32px` 与默认上下留白冲突；任务/更新 content 只约束 flex 与 overflow，滚动由内层 ScrollArea 承担。窄窗/文字放大时同时检查 Modal.inner 无第二层原生滚动条和底部按钮可见。

配置页右下角：未安装显示“一键安装”，已安装显示“一键卸载”。已安装且有草稿时，“保存配置”为主要动作，卸载为次要危险操作；保存只写必要配置，不重装健康组件。部分缺失/损坏显示统一修复/恢复入口，仍允许完整卸载；不能只凭目录存在判断安装完成。核心缺失时的安装在同一任务弹窗完成一次应用确认，先原生安装 MPV，再部署增强与配置。

画质默认均衡，仅在首屏选择框旁显示对应档位的简短建议；不检测硬件，不展示显示器、分辨率、显卡、供电信息或自动推荐操作。具体文案与预设取舍见 [播放默认值](../v0.1.5/playback-defaults.md)；完整卸载边界见 beta.1 方案。

HDR 默认自动，三态操作仅在 uosc 菜单提供。音轨与字幕语种不提供 GUI 控件（包括高级区），默认汉语→日语→英语→西班牙语；播放器界面语言独立使用管理器安装时的实际语言。语种标签依据与文件手改约束见 [播放默认值](../v0.1.5/playback-defaults.md)。

设置采用完整页，语言与外观、MPV、应用更新成组。MPV 只显示版本、状态、包管理器来源和一个安装或管理入口；默认应用快捷操作放入已安装核心的管理菜单。应用更新单列，应用版本附在更新行，保留检查更新按钮。关于简化为仓库链接按钮，不再堆放简介或许可列表；随包许可材料及检查保留。主题和语言默认跟随系统、即时反馈；播放器配置需明确预览和保存。切页不隐式保存或取消任务。

仓库入口采用一个简单次要按钮，内容为本地单色 **GitHub 图标 + Leovikii**，通过系统浏览器打开固定 MpvKit 仓库；不再展示“Repository / 仓库”标题行或完整网址。图标不远程加载、不新增图标库；按钮保留键盘操作及明确的可访问名称“在 GitHub 查看 MpvKit 仓库”。删除版权许可证整行的标题、GPL 文字、Copyright & license 和 Third-party notices 按钮，不留空面板或多余分隔线；随包许可证文件及声明继续保留。

## 对话框与文案

beta.2 预设更新仅作页内简短提示：旧修订显示“预设已更新”，未记录完整应用显示“可重新应用配置”，操作统一为“重新应用配置”；英文及确认风险文案见 [beta.2 方案](../v0.2.0-beta.2/plan.md#提示文案)。确认处用“按当前设置覆盖配置手改，无备份。”并展示目标与差异；不在页内解释修订号、摘要或版本管理实现，不自动覆盖、不反复弹窗催促。

已接受交互：提示放在配置页主设置上方，使用现有 Mantine 信息提示与同处操作按钮，不能藏在高级项或只用短暂通知。启动/升级后重启/回焦均不自动弹窗；仅用户点击后进入已有预览/确认任务弹窗，一次确认后执行。提示随实际修订状态存在，成功后消失，失败/取消后保留；不新增忽略版本、已读或提醒偏好的持久状态，不抢焦点、不显示为配置损坏。非紧急预设提示显式使用 role=status 与礼貌播报，不沿用 Alert 默认的紧急播报语义；真实错误仍使用 alert。

2026-10-22 最终审阅：删除界面中不影响当前选择的说明，包括默认语种顺序、如何编辑 mpv.conf、默认行为罗列和重复推荐句。技术依据留在开发文档；保留“打开配置文件夹”按钮。页面不在菜单或选项之外堆放常驻说明段落（如“推荐配置即可开始播放”“默认记忆播放位置”“写入前会显示具体变更”）；需要的选项说明就近作为副标题。独立设计预览必须同步遵守此规则，不能遗留旧文案误导审阅。菜单与按钮优先使用短动词/名词，中文和英文同时精简。HDR 自动/关闭不附解释，只有强制开启时提示使用条件；画质建议仍就近显示。保留当前错误、冲突、覆盖授权、删除/重置后果和必要状态，不以精简为由隐去风险。

默认宽约 560，复杂文件差异最多 720，窄窗限制为视口减 32。内容可滚动，操作区始终可达；不叠加第二个确认弹窗。

短确认弹窗按实际标题/必要短正文/按钮自适应高度，不沿用长日志任务的空白占位。标题和正文保持同一表面，操作区可轻微分区，但不能在中间留下无内容色带。页面卡片的 Paper 背景须限定作用范围，避免影响 Modal；不叠加多套操作区 margin/padding。alpha.4 已修复退出确认的空白色带；共享样式调用方包括任务、更新及退出弹窗。

顺序：动作标题 → 简短影响摘要 → 固定目标 → 冲突/保留内容（如有）→ 可展开文件明细 → 执行、取消。主按钮叫“安装”“保存”“卸载”，不泛称“确定”。默认不展示原始 JSON；技术详情仍可展开。手改冲突及执行阻断不能被摘要隐藏，不能因视觉精简绕过预览、复核或当前操作失败恢复；不保留历史备份、撤销及手动组件缓存清理。

统一卸载在同一弹窗展示实际目录，并提示“将删除此 MPV 配置目录及全部内容，包括其他脚本、手改配置和续播记录。”核心存在时提供“同时卸载 MPV”复选框，建议默认不选；一次应用确认后，若勾选则先等待原生卸载结果，随后执行配置删除。核心失败/取消/无法启动仍继续已确认的目录删除，分别报告两项结果并只重试失败阶段。设置内独立核心卸载保留配置，文案需区分入口的范围。

任务的确认、进度、成功、失败及重试留在同一 Modal。配置与组件安装先显示本地具体预览，确认后才下载；下载完成不再要求第二次应用确认。包管理器询问和系统授权保留原生界面，不自动代答；“等待包管理器”用不确定进度，不假装可控制原生进度。必须等待真实命令退出，不能把启动终端成功或关窗当作操作成功；任务中不以应用取消强杀包事务。只有安装命令成功并复核核心可用，才继续配置部署。

危险操作默认聚焦取消；普通操作保留安全可达的取消。不对默认安装目录弹出“修改目录”确认。媒体登记交给系统 MPV 包；默认应用快捷入口只打开系统设置，不得声称已设为默认播放器。

文案面向用户：说明对象、状态、下一步。优先“尚未安装”“生成配置”“配置已保存”“修复播放器”。不要“初始化部署流程”“目标环境健康性”等术语。每段原则上一至两句；语义需要时允许更长。中文和英文同等支持，禁止只缩短中文而让英文溢出。

## 动效规范（2026-10-22 补充）

依据微软 [Page transitions](https://learn.microsoft.com/en-us/windows/apps/develop/motion/page-transitions)，既有页面切换采用 Page refresh，即新内容向上进入并淡入；更深层详情才适合 Drill，横向同级导航才使用横向滑动。beta.1 按用户要求继续保留现有过渡，设置/返回不另加横向滑动。这里的 Page refresh 指视觉过渡，不是重新加载应用或执行刷新接口。参考 [Animations overview](https://learn.microsoft.com/en-us/windows/apps/develop/motion/xaml-animation)，优先保留标准控件内建动效，以状态反馈为目的，避免分散注意力。

| 场景 | Mantine 实现与项目选择 |
| --- | --- |
| 配置/设置切页 | 内置 Transition `fade-up`，进入 200 ms、ease-out；使用库自带 30 px 位移，不写自定义关键帧。旧页立即移除，只动画新页，不移动标题栏/窗口外壳。该参数是本项目选择，不是声称复刻 XAML 动画时间曲线。 |
| 页面承载 | Transition 官方主要面向 fixed/absolute 的呈现；在固定内容面内放置绝对定位、独立滚动的页面层。只保留一个页面，避免两个可交互页面重叠。 |
| 高级选项与组件详情 | Accordion 内建高度、淡入淡出及箭头旋转，180 ms；不另写高度测量或折叠动画。 |
| 确认弹窗 | Modal 的 transitionProps：内置 fade，进入 160 ms、退出 120 ms；保留焦点锁和返回焦点。 |
| 工具提示 | Tooltip 内建 fade，进入 120 ms、退出 90 ms；保留悬停及键盘触发。 |
| 按钮、选择框、复选框、菜单 | 保留 Mantine 原有悬停/按下/选中反馈与可用的内建过渡；没有动画的原生控件不另造替身，不增加弹跳、波纹或逐项进场。 |
| 异常与进度 | 保持即时可见，不能等待动画才提示失败、允许取消或阻止危险操作。不让每次进度更新重播整个页面。 |

时长统一在 theme.defaultProps 或唯一页面过渡处管理；不加动画依赖、路由动画框架、通用动画状态机或全局 `transition: all`。不为实现退出动画延迟业务切换。切换过渡仅随 page key 发生，编辑参数、主题切换和状态刷新不重播页面；快速连续切换以最后选择为准，组件负责清理动画计时。

开启 `theme.respectReducedMotion=true`，尊重 `prefers-reduced-motion`；保留减少动态效果的 CSS 兜底，以同时覆盖 Accordion 箭头等 CSS 动效。系统偏好关闭动画时页面直接出现，不能残留透明、位移、隐藏焦点或等待定时器。产品实施还需在 WebView 中验证 Windows“动画效果”开关的映射。

验证增加：正常动效与 reduce 两种模式、快速切页、再次点击当前页不重播、切页不丢草稿/下载、关闭弹窗动画后的焦点归位，以及长内容滚动位置正确重置。预览只演示页面和现有组件动效，不新增产品动画开关。
