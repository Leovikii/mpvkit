# uosc 控件与 Linux 启动窗口优化（已批准并实施）

2026-10-26。用户先要求调查与方案，随后批准“左侧仅三控、右侧直接分组”实施。用户特别说明随手调整的底色数值不作为依据；最终按原生白底/深色实播选择 55% 中性深色衬底、24 逻辑像素渐隐和 18% 悬停提亮。没有新增布局选择设置。下文保留调查与备选比较，当前实现及验证边界见末节；不是仍待批准的方案。

## 调查结论

三项问题需要分别处理：中央按钮尺寸偏小且缺少底色；字幕与中央三控交叠；倍速仍使用刻度条。窗口偏小另有已复现的 Wayland 多屏启动时序原因，不能靠放大 uosc 或增加 DPI 倍数解决。

### 实施前控件的真实状态

- 固定 uosc 5.13.0 默认 controls_size=32、text_border=1.2、opacity.controls=0；本项目 uosc.conf 仅覆盖排列，尚未覆盖这些视觉参数。本机 150% 缩放下，实际按钮框为 48×48 物理像素，图标字号为 34；换算后仍是 32 逻辑像素的按钮。DPI 已生效，问题是基准偏小、背景透明、切集图标偏细。
- 合成白底实播中，上一集/播放/下一集均启用、visibility=1，播放按钮仍精确居中；没有被溢出算法收起。去掉字幕后能看见轮廓，加入居中字幕后中央三控与字幕争用同一区域，复现用户截图现象。透明小按钮使交叠更难分辨，不能仅换颜色便视为解决。
- 实施前主栏直接配置原生 speed 控件，其行为就是刻度/拖动。mpvkit.lua 已有六项 speed-menu，但尚未绑定为主栏倍速入口；不需要重新实现一个菜单系统。

取证使用固定 ZIP、当前 bridge/mpvkit.lua 与 uosc.conf 的临时副本、合成白色视频和字幕。临时副本追加只读布局观察接口；没有修改上游归档、仓库资源或用户文件。实测原始记录在本机 /tmp/mpvkit-v018-window-investigation，整理见 [调查数据](uosc-window-investigation.json)。

### 75% 窗口为什么变小

本机主屏 DP-1 为 3840×2160、150% 缩放，逻辑尺寸 2560×1440；副屏 DP-2 为 2560×1440 旋转竖向、150%，逻辑尺寸约 960×1707。官方 v0.41.0 Wayland 实现未指定屏幕时，先取输出列表首项估算启动尺寸，窗口实际落屏后才收到 surface-enter。

本机日志明确显示：先用竖屏的 **1440×2560** 计算 autofit，再进入 **3840×2160 的 DP-1**。实际窗口最终仍为约 **1080×608**，相当于 4K 宽度的 28.1%；不是预期的 75%。16:9 内容在 4K 主屏内的正确目标为 **2880×1620 物理像素 / 1920×1080 逻辑像素**，75% 指宽高边界，不是屏幕面积占 75%。

用同一 1280×720 合成视频、系统 MPV 0.41.0、无用户配置/脚本的独立进程验证：

| 临时实验 | 最终渲染尺寸 | 结论 |
| --- | --- | --- |
| 当前两项窗口默认值 | 1080×608 | 先按竖屏算，落到主屏后偏小 |
| 仅将 auto-window-resize 改为 yes | 1080×608 | 不解决首次落屏时序，且会破坏切集保持尺寸的设计 |
| 临时指定 screen-name=DP-1 | 2880×1620 | 以正确输出估算可得到设计值；不是通用产品修复方案 |
| 指定 DP-1 并启用 hidpi-window-scale | 2880×1620 | 额外 DPI 倍数没有带来修复收益 |
| 默认启动，实际进入 DP-1 后重新设置同一个 autofit 值一次 | 1080×608 → 2880×1620 | 原生重算能力可用，是最小修复入口 |

上述参数仅传给临时进程。没有更改屏幕模式、缩放、窗口规则、实际配置或默认应用。此前 Linux 验证只记录了 autofit 参数与 1080×608，没有对照真实落屏尺寸，未覆盖本次缺陷。旧 Windows 单屏尺寸证据不受此发现替代。

## 布局比较与推荐

用户进一步提出“左侧只保留三大控制键，其他全放右边”，本次据此收敛为 **左侧仅上一集 / 播放暂停 / 下一集，右侧按功能分组**。先前“靠左集中”示意仍把菜单、信息和轨道紧邻三控，未充分分开操作目的；逐键深色方框又把所有入口画成同等重要，确实增加辨认负担。

推荐排列（括号只表示分组留白，不画常驻框或竖线）：

```text
[上一集 播放/暂停 下一集]        [音轨 字幕]  [1× 播放模式 播放列表]  [信息 更多 全屏]
──────────────────────────── 原生进度条 / 缩略图 ─────────────────────────────
```

- 左侧固定三控，只有一个弹性留白把其余功能推向右边；不在三控旁追加菜单、时间文字或轨道。进度条上下顺序先沿用原生 uosc，本轮不重写布局。
- 右侧由内容选项、播放行为、工具/窗口三组构成，用约 12–16 的留白区分。全屏始终最右，“更多”在全屏左侧；播放信息在宽窗仍保留独立入口，延续本版已批准要求。
- 倍速显示当前数值并点击选列表；播放模式显示当前状态图标并点击选列表；播放列表使用列表图标。模式和队列采用可区别的图形及短提示，不能全用相似的循环/横线图标。
- 原菜单入口改用“更多”的省略号语义，仍通向原生菜单，不另起一套导航；新收起的入口从这里可达。音轨/字幕保留直接操作，避免为了视觉空白让常用切换多点一步。
- 窄窗按优先级收起信息/音轨，再收起字幕/模式/列表，极窄时倍速也收入更多。三控、更多、全屏不缩小、不换位置；以实际内容宽度判定，需调整现有 bridge 的宽度信号，不能把示意断点直接当成原生验收结果。

精简备选把音轨/字幕收入“设置”，保留右侧倍速、模式、列表、设置、信息、更多、全屏。它更疏朗，但轨道操作多一层，且“设置”和“更多”职责容易重叠，因此不作为首选；若选择此案，需明确设置只管播放选项，更多只管文件/工具。独立示意提供两案对比，均是左侧仅三控。

居中方案保留为调查中的比较结论，不再作为推荐示意：它符合传统播放器习惯，但本机已实测与居中对白字幕交叠。左侧方案更适合本项目的连续切集及字幕场景；长行、双语和 ASS 仍须验证，不能宣称布局能杜绝任何字幕遮挡。不长期抬高 sub-pos 或移动已定位的 ASS 来为控制栏腾空间。

两案继续使用 uosc 原生 prev/next、pause、items、菜单及键盘处理。侧边音量、背景单击无操作、双击全屏和空格暂停保持既有行为。只选择一套默认布局，不增加永久的自由编排或布局切换设置。

## 建议的尺寸与对比度

以下为批准的视觉目标；底色以实播后的取值为准，按逻辑像素表达，不把 4K 的物理像素当作界面尺寸：

| 项目 | 建议 |
| --- | --- |
| 播放/暂停 | 48×48，原生播放/暂停符号和轻微提亮的圆角热区；不再用孤立的大圆盘，与同组控件保持同一基线 |
| 上一集/下一集 | 44×44，采用辨识度更强的 skip_previous / skip_next 图标，仍执行 uosc 原生切集 |
| 次要入口 | 热区至少 44×44，图标约 22–26；用较小图形表达层级，不压缩点击范围 |
| 留白 | 三控间约 6–8，功能组间约 16，窗口边缘约 12；不挤压进度条 |
| 底色 | 优先统一底部中性深色衬底，上缘柔和过渡，控件区域采用 55% 不透明；按钮平时透明，不逐键画深色方块。白图标配细暗描边，随原生控制栏隐藏 |
| 悬停/选中 | 悬停只在当前热区短暂提亮；图标始终清楚，不能白底白图标。当前模式/倍速在列表里明确标记，不用常驻底框表示菜单能点击 |

基准从 32 提升到 44 为主；播放按钮再作小幅强调。本机 150% 下对应主按钮约 72×72、切集约 66×66 物理像素；全屏缩放继续由 uosc 原生 scale_fullscreen 与显示器 DPI 处理，不重复乘缩放。

已用原生 controls_size、text_border 和 command/managed button 配合现有 bridge 实现。bridge 只修饰原生按钮渲染与缩放比例，添加一个沿原生可见性显示的衬底元素；24 个有界矩形完成短渐隐，不新增绘图库或计时器。按钮命中、延迟分发、轨道角标、控件坐标和菜单导航仍复用上游。悬停从上游 30% 白色填充减至 18%，避免浅底下白图标失去对比。两平台原版、扩展和部署摘要及修改说明已同步。

示意中的字幕位于控制栏上方，只表达阅读区域，未实现或证明原生自动避让。当前预览中的图标为概念示意，最终应优先使用固定 uosc 图标集中含义明确的一致字重图形；不为示意引入 Web 图标依赖。640/900/1200 逻辑宽度、高 DPI、纯音频及不可切集状态均需原生验收。

## 倍速按钮与列表

主栏把刻度条替换为 managed button，直接显示当前倍速，例如 1×、1.25×；点击打开原生 uosc 列表，行为与播放模式一致。固定选择为 0.5×、0.75×、1×、1.25×、1.5×、2×，标记当前项；鼠标、方向键、Enter 和 Esc 使用原生菜单行为。设置只改变当前 MPV speed，不写入 GUI 设置或续播记录。

复用现有 speed-menu，并监听 speed 更新按钮文字/标记及已打开的列表。外部快捷键改为 1.1× 时应如实显示，不回跳或错误勾选某一预设。uosc 原生 managed button 公开支持图标/角标，不直接支持任意普通文字。已在 bridge 为指定 managed button 增加居中文字渲染：直接读取当前 speed，以原生 hitbox 与延迟点击打开现有列表；没有将角标或图标错误地当作文字 API。

## 启动窗口的建议修复

保留 autofit=75%x75%、auto-window-resize=no 的设计。建议只在 **Linux Wayland 首个视频窗口建立、实际输出已可用后，按当前 autofit 重算一次**；调用已经实验通过的 MPV 原生选项，不自己计算 75% 像素。

- 只处理首次窗口初始化。切集、跨屏拖动、手动调整之后不再次强制套用 75%；不增加常驻窗口追踪器或窗口尺寸数据库。
- 使用当前有效的 autofit，尊重用户配置；显式 geometry、全屏/最大化、平铺锁定或初始化期间已发生的用户尺寸干预须跳过。手动干预的判定与事件竞争需要专项验证，不能用固定长延时直接覆盖。
- 不固定 DP-1、不把主屏名称写进共享配置，不扫描屏幕/显示器。Wayland 窗口位置由合成器决定，“初始选屏提示”不能当作强制落屏保证。
- 不打开 auto-window-resize，不通过 hidpi-window-scale、全局 window-scale 或反复切换临时比例补偿。
- 不用 display-width/display-height 直接推导目标：本机该属性返回 4800×2160，而当前屏幕实际为 3840×2160；存在多屏聚合含义，不能当成单屏尺寸。
- Windows 沿用目前原生窗口行为，本轮 Linux 问题不作为改动 Windows 调窗的依据。

已在 mpvkit.lua 观察首个实际 display-names、vo-configured、video-out-params 和初始 osd-dimensions；就绪时同步重设当前 autofit，然后注销本组观察，不使用固定延时、无界重试或常驻调窗。显式 geometry、非默认 window-scale、全屏/最大化/最小化、auto-window-resize 开启、初始跨多块输出，以及等待期间超过 2 物理像素的尺寸变化均直接停止。2 像素容差仅容纳初始 607→608 一类取整；不能据此保证极短竞态或所有混合缩放环境。平铺由目标 MPV 的 locked_size 原生机制保留当前几何尺寸；本机平铺及物理拖动竞态尚未实测。

## 实施与验收范围

本轮在全新隔离根实施与验证，保留以下验收范围作为回归入口。

1. 本机双屏 150%：记录初始估算屏幕、实际落屏和最终物理/逻辑窗口；720p/1080p/4K 同比例媒体应得到相同的 75% 边界。竖屏/超宽保持比例。手动缩放、切集、全屏往返不被重置。
2. 两种背景、普通/双语/ASS 字幕：检查图标和热区、字幕可读性、悬停、暂显/隐藏。验证播放、上一集和下一集真实动作；未出现把切集改为章节或快进。
3. 倍速按钮实际点击打开六项列表，当前标记正确；选择、取消、外部 1.1× 更新、重新打开、键盘操作均验证；删除主栏刻度/拖动入口。
4. 窄窗与缩放下左侧仅三控、右侧组间距清楚；收起入口可从更多访问，信息在宽窗独立。倍速/模式列表不因鼠标点击穿透而暂停。
5. Rust 格式/静态/相关测试、两平台来源摘要、Windows 可行检查与 Linux 原生实播；获批后才重建单 ELF，Windows 真实原生验证不可用则如实列明。

当前已实施左侧三控与右侧直接分组，放弃精简设置备选；44/48 尺寸、透明次要按钮、55% 统一衬底、当前倍速文字及原生列表已接入。首轮完整隔离 Wayland 回归通过；最终扩展尺寸矩阵已通过；结果及产物摘要见 [实施证据](evidence.md#uosc-布局倍速和-wayland-启动尺寸实施2026-10-26)。白底、深色、悬停、SRT 与定位 ASS 已原生渲染查看；长双语/任意定位字幕仍可能覆盖次要按钮，不移动用户字幕位置。没有 CI、安装包、兼容迁移或提交/推送。
