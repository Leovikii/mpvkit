# v0.1.1 界面与交互流程

更新日期：2026-10-21，审核修订第 2 轮。状态：已实现；实际验证与桌面限制见实施证据。范围以[版本方案](scope.md)为准；产品文案与工程说明分开，本文件的技术解释不直接复制进界面。

## 页面结构与平台步骤

首次引导：安装位置 → 安装组件 → 播放设置 → 系统集成。常规启动检查后进入状态页；初始化期间只展示当前步骤，日常功能不同时堆在下面。

“系统集成”是内部通用步骤名。Windows 显示“添加到打开方式”，准备稳定启动入口并登记媒体类型；设为默认仍由用户在 Windows 中选择，不是完成条件。Linux 未来按实际情况提供应用菜单入口和 MIME 打开方式：发行包已经完成且指向正确受管理启动入口时直接跳过，否则提供补齐操作。系统已有一个指向原始 mpv 的 desktop entry 不代表已加载 MpvKit 配置。无可用桌面环境时显示适用限制，不显示空的 Windows 页面；具体 Linux 完成条件在该版本确定，本版不实现。

步骤身份使用稳定 ID（location/components/playback/integration），计数和标签来自当前可见步骤；不在持久化记录中把“第 4 步”作为平台无关真相。不为未来 Linux 建立通用工作流框架。

## 用户文案规范与首批中英对照

默认不为每个字段写说明；标题说明当前任务，按钮说明动作，提示只在用户需要选择或遇到问题时出现。一个状态对应一句话，避免“归属”“代际”“核验链”“结构化设置”等内部词汇。按钮使用“安装”“保存”“重试”，不要用“执行本次计划”。

## 第 1 步：安装位置

标题“选择安装位置”，显示当前有效路径；主按钮“继续”。默认使用系统推荐目录。“高级选项”默认收起，内含默认不勾选的“自定义安装目录”；勾选后显示路径输入和系统目录选择器，取消勾选立即恢复默认位置。重新打开已有自定义安装时保留已选路径和勾选状态。

路径没有变化时直接检查并进入组件页，不弹确认、不写目标记录；实际切换路径才展示新旧位置并确认。选目录本身不接管、搬移或删除文件。“使用已有 MPV”收进“高级选项”；移除配置布局选择，已有管理布局由后端识别并保留。新安装的播放器和配置位于同一根目录的 runtime、config 子目录。无法访问目录允许重选或重试，不自动覆盖。

## 第 2 步：安装组件

建议只保留两个分组，不增加多个同级脚本卡片或引入额外标签页：

| 分组 | 默认展示 | 展开后 |
| --- | --- | --- |
| 播放器 | MPV、已装/可用版本、状态、核心下载量 | 必要运行依赖、来源与详细版本 |
| 播放增强 | “播放界面和缩略图”、项数、汇总状态、扩展下载量 | 播放界面（uosc）、缩略图（thumbfast）的版本与各自状态 |

MpvKit 必需的配置、档位/保存脚本属于受管理基础能力，不列为可选增强。uosc 所需字体/helper 等依赖放在所属组件详情，不让用户逐项决定是否安装。

本轮仅改变展示分组，保持“播放器＋默认播放增强”整套安装；不新增开关或“仅安装核心”模式。这样无需承担组件选择、依赖求解及 uosc 缺失时默认 OSC 切换等额外范围。未来若用户确实需要最小安装，再单独设计；折叠不表示可跳过。首次全部必要组件通过后才可进入播放设置；已完成环境的脚本缺失沿用既有基础播放降级并提示修复。

- 默认增强组折叠；仍显示“2 项 · 待安装/下载中/已安装/需要修复”，不能隐藏失败。
- 发生增强错误或冲突时自动展开对应组；不在下载每次进度更新时反复折叠/展开，保留用户操作。
- 全页一个主操作，按阶段显示“下载组件 → 安装 → 继续”。不会为每个脚本摆一个下载按钮。已经就绪的文件不重复下载。
- 下载显示总量/分组状态，未知总量显示当前阶段，不编造总体百分比；取消如实显示“正在取消”直至实际停止。
- 安装预览用分组摘要，具体替换/冲突显式列出；文件详情可展开。执行仍逐文件核对、备份和恢复，不因视觉分组改变原有事务边界。
- 目标 MPV 缺失、下载/验证失败时不开放下一步；提交后不显示无法兑现的即时取消。

## 第 3 步：播放设置

标题“播放设置”。进入时自动检测；首屏摘要只显示屏幕分辨率、GPU 和 HDR 状态，供电仅在影响推荐时说明。“自动检测”不是一个强制下一步按钮。

| 项目 | 默认呈现 |
| --- | --- |
| 播放屏幕 | 下拉选择；多屏名称加分辨率；手动宽高在“自定义分辨率”展开 |
| 画质 | 省电 / 均衡 / 高画质；推荐项带“推荐”，理由可查看 |
| HDR | 自动 / 开启 / 关闭；需要开启系统 HDR 或能力未知时才显示原因 |
| 音轨语言 | 默认轨道，或有序语言列表 |
| 字幕语言 | 独立有序列表，不暗示强制显示字幕 |

不显示字幕字号、音量和 OSD 大小；沿用基础值，保留旧用户覆盖。次要操作“重新检测”“打开配置文件夹”，不长期显示整段配置说明。有 user.conf 才提示可能覆盖。分辨率仅用于播放建议，不改系统显示模式；这条说明放在自定义分辨率入口处。

主操作“保存并继续”，提交区给出修改摘要和必要风险；保存成功再进入系统集成。重新检测不覆盖手动选择。离开未保存编辑时确认，语言/主题切换则直接保留草稿和当前预览状态。

## 第 4 步：系统集成（Windows）

标题“添加到打开方式”，一句说明：“从资源管理器使用 MPV 打开媒体。”主操作同名，不用“登记到 Windows”。必要入口文件与媒体类型在确认区说明，完整路径和登记值可展开。

先准备稳定启动入口，再登记当前用户打开方式；失败留在本步，已安装组件保留。成功显示“已添加到打开方式”，提供“默认应用设置”和主按钮“完成”。不要求用户更改默认播放器，不显示未经核实的“已设为默认”。

Windows 正常初装仍须完成该步骤；退出保留进度，下次继续。已完成后登记失效进入状态页修复，不强制重走初装。Linux 的按需步骤原则见本文开头，不将 Windows 注册表文字直译到其他平台。

## 状态页、维护和应用设置

| 页面 | 用户任务 |
| --- | --- |
| 状态 | 确认已就绪、看当前方案、打开视频；显示需要处理的问题 |
| 播放设置 | 复用引导表单，保存后留在原页，提示下次启动生效 |
| 组件与更新 | 保持播放器/播放增强两组；查看已装与可用版本、更新或修复 |
| 系统集成 | 查看、修复或移除打开方式；进入默认应用设置 |
| 维护 | 恢复、诊断、清理、移除；危险操作单独分组 |
| 设置 | 语言、外观、关于；包含版本、仓库、版权/许可和验收状态 |

“打开视频”保留后端检查和执行前重查，正常播放无需每次阅读启动参数；异常时先解释并停止。已安装/文件正常不等于播放效果已验证，完整开发验收状态放“设置 → 关于”，当前用户确实会遇到的限制仍就地显示。

用户已认可单独的应用设置功能。对用户统一命名为“设置”，将“关于”纳入其中，不再保留独立“关于”侧栏项。页面按“语言”“外观”“关于”分组；分组内容可直接阅读，第三方声明等长内容进入详情，避免再次变成长文档首页。

设置不增加引导步骤：向导右上角提供入口，打开同一设置内容的临时面板，返回保留步骤与草稿；日常侧栏底部进入独立设置页。语言和主题即时预览并保存应用偏好，不重新检测设备、不清空草稿、不重启下载。系统对话框仍使用操作系统语言，不承诺跟随应用手选语言。

| 设置 | 选项与默认 |
| --- | --- |
| 界面语言 | 跟随系统（默认）/简体中文/English；显示语言自身名称，错误选择后易于恢复 |
| 明暗模式 | 跟随系统（默认）/浅色/深色 |
| 强调色 | 系统色（默认）/蓝/青/紫/橙等小组已校验配色；色名和选中标记可读，不靠颜色区分 |
| 窗口背景 | 自动采用系统支持的 Mica，否则使用对应主题纯色；不显示设置项 |

“关于”包含应用版本、已确认仓库链接、项目版权/许可证、第三方声明，以及必要运行环境和验收状态。长许可证正文进入只读详情，不默认展开；仓库地址必须来自确认的产品元数据，不能猜测。播放设置、组件操作和危险维护保留各自页面，不全部塞入应用设置。

界面语言与媒体语言完全独立：切成英文不会改变音轨/字幕顺序。强调色用于选中、焦点和主按钮，不把 Mica 底层染成整片品牌色。配色不等于状态色，成功/错误始终有文字。

## 应用图标

使用用户于 2026-10-21 提供的 [MPV SVG](assets/mpv-logo.svg) 作为应用品牌图标，保留原始 path、24×24 viewBox 与 mpv 标题；按用户后续反馈，产品改用经预览确认的浓紫色 #A84BD6，原始设计源仍保留 #691F69，不随强调色改变；产品名称仍为 MpvKit。标题栏、设置 → 关于及未来桌面/任务栏图标统一使用该图形，不以字母 M 代替。导航和操作图标仍表达各自功能，不全部替换为 MPV 标志。

预览按 24 px 等比显示；按用户最终意见使用无边框、无浅色底衬样式；保持原 SVG 填色，检查深浅主题辨识度。独立 SVG 保留可访问名称；与重复文字组合时按实际上下文去重朗读，不把图标当作无标签操作按钮。

正式开发 U1 从同一 SVG 生成 Windows 所需多尺寸 ICO/PNG，验收标题栏、任务栏、桌面和关于页在不同 DPI 下的清晰度及浅/深/高对比度表现。本轮仅保存设计源文件和替换模拟预览标识，不生成或替换产品安装包图标。来源记录为用户提供，公开分发前按既有来源政策核对图标原始来源和适用许可，不据聊天输入推定许可；关于页收录核实后的归属信息。

## Windows 视觉与 Mica

保留 Tauri 2 + Mantine。建议初始 1040×760，最小 640×600；原生缩放、窗口按钮、拖动、最大化、Snap 和系统菜单保持。宽窗约 208 px 侧栏，不足 900 px 折叠；正文边距 24 px/窄窗 16 px，使用 4 px 间距体系。正文 14–16 px，标题 24–28 px，系统字体加中文回退；这是项目设计起点，不是 WinUI 的强制值。

采用标准 Mica 作为一个顶层窗口背景，首选“连续内容面”组织设置行；只在需要独立摘要时用卡片。按 Microsoft 的底层/内容层层次：

1. Mica 用于窗口底层，优先在标题栏、导航与留白体现。
2. 主内容区覆盖有可读对比的中性、低透明度表面；输入框、菜单和对话框保持清晰，不能全页穿透。
3. 弹窗用常规表面和遮罩；本版不增加 Acrylic 或 Mica Alt。应用中只应用一次窗口材质，不对每个卡片调用材质 API。

Mica 是融合主题与壁纸色调的不透明系统材质，不是透视后方窗口的实时模糊；不使用 CSS backdrop-filter、壁纸截图或装饰渐变冒充。默认尊重系统透明效果、节电、高对比度和焦点状态；不支持、策略要求或失败时回退为同主题纯色，基本功能完整可用。

原生标题栏优先保留。Microsoft 建议标题栏可见 Mica；先验证当前 Tauri/DWM 路径能否覆盖非客户区与 WebView2。若需要扩展内容到标题栏，再评估受控标题栏区域，同时保留系统窗口按钮和命中测试；不为材质全面自绘标题栏。具体支持构建与验收见[架构增量](architecture.md)和[验证要求](verification.md)。

## 体验反馈：高级选项

自定义功能统一收进默认折叠的“高级选项”。安装页收纳自定义目录及已有 MPV；组件页收纳覆盖已有文件与来源详情；播放页先展示检测结果和推荐值，分辨率、画质、HDR、语言顺序和打开配置目录置于高级选项。下载、继续、保存并继续等主要操作始终可见，默认值可完成引导。应用语言、明暗和强调色仍留在独立设置页。折叠只改变展示，不丢失编辑值，也不跳过覆盖预览。
