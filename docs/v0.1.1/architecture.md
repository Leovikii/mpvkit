## 根目录、标记与信任

默认根沿用 Known Folder LocalAppData/MpvKit。活动目标记录始终在默认根下；自选根的安装数据属于该目标，切换不搬移。现有备份和暂存实际在 .mpvkit 下，不为了匹配概念图迁走它们。

~~~text
默认根/.mpvkit/target.json       当前活动目标指针（已有）
默认根/.mpvkit/app-settings.json 应用语言和外观，与活动 MPV 目标无关
所选根/
  runtime/                       受管理 MPV 文件（已有）
  config/                        默认配置布局（已有；旧直接布局保留）
  state/settings.json            结构化设置，v2，显式迁移旧设置
  cache/                         现有会话等数据
  launcher/mpvkit.exe             单 EXE 模式稳定短时入口
  .mpvkit/
    owner.json                   已有归属标记，不是可信来源证明
    install.json                 已有部署成功清单、文件摘要、代际
    pending.json / previous.json 已有恢复记录
    associations.json            已有登记归属记录
    association-pending.json     已有登记恢复记录
    playback.json                已有全局档位偏好
    setup.json                   最小引导进度记录
~~~

只复用已有标记，不新增根目录 success.txt 或把“installed=true”作为真相。归属 JSON 可以被复制/编辑，读取成功仅表示记录可解析；就绪必须核对路径边界、清单、相关运行文件、配置和组件身份，再按既有可信来源与能力检查规则决定是否允许运行。未知 schema、畸形记录及摘要不符保持原样，禁止自动修复覆盖。

综合检查应先做本地只读文件核验，再执行允许的有界版本/参数查询；外部 MPV 首次查询须用户明确选择。自动启动不扫描全部磁盘、PATH 或远程盘。失效路径必须有界返回；使用已有拒绝 UNC、映射网络盘、reparse point 的平台保护。

## 启动报告与引导状态

已新增聚合业务入口 setup_status，返回根目录、目录布局、安装身份/代际、核心程序和各组件健康、配置兼容性、登记实际状态、待恢复操作、阻止原因及可继续的阶段。后端 setup.rs 组合已有业务；commands 仍只负责参数、线程调度和调用。

React 用一个顶层控制器维护当前页/步骤、草稿和正在进行的操作。全局只存当前根与报告、活动操作；表单状态就近管理。无需新状态库、路由库、通用工作流引擎或全局事件总线。通过操作成功后的明确刷新更新页面；迟到响应必须携带目标身份并被丢弃，切换目录或请求失效不能污染新页面。

setup.json 实际字段为 schemaVersion=1、owner、environmentId、settingsHash、completed。environmentId 对应安装清单新增的可选稳定身份，更新保持、重装更换；老清单以 installationId 迁入。登记是否有效始终读取实际登记值，不另存成功布尔值。遵守以下语义：

- 记录仅指示用户已完成哪些选择，不能解锁缺失的组件；组件健康从实际文件推导。
- 目录选择、安装、设置应用和登记各自成功之后才写相应进度；进度失败可从实际成功状态重新确认，不重复覆盖或重复下载。
- 偏好确认绑定设置内容/修订，完成状态绑定安装身份而非每次更新的代际；日常修改设置或更新组件不重新触发初装向导。
- setup.json 写入使用已有原子写与锁，明确纳入本应用元数据归属；读取未知版本停止写入。安装、配置、登记业务本身的恢复记录始终优先。
- 重启不持久化下载字节和临时预览；下载中断需重新准备。已提交阶段保留，未保存表单可丢弃并明示；不承诺任意时刻无损恢复草稿。
- UI 跳步限制外，设置写入和系统登记的后端前置条件也要统一检查。并发进程、目录更换、过期预览仍按原有锁及摘要拒绝。

v0.1.0 无 setup.json：有效清单、可读设置、必要组件完整且实际登记有效时，直接进入状态页，提示可配置新增偏好；没有登记则从第 4 步继续，配置不完整则定位到相应步骤。新进度或设置迁移必须展示预览后写入，启动只读检查不偷偷改旧环境。

## 设置模型与推荐

settings 拟升至 v2，显式支持 v1 读取与迁移。保留 profile 和已有 overrides；增加目标屏幕/自动或手动分辨率、HDR 意图、音轨与字幕的语言顺序，以及区分自动推荐/用户覆盖所需的最小字段。设备快照是事实，不应复制到用户设置后冒充持续有效的硬件状态。

v1 → v2 保留旧字幕/OSD/音量/硬解覆盖、三档及 user.conf，新增字段使用自动或媒体默认值；迁移在设置应用预览中说明，按现有部署事务备份。v0.1.0 遇到 v2 应明确拒绝，不承诺直接降级可用；恢复到上一成功 v1 快照后才可用旧应用。不能先覆盖原文件再宣称可迁移。

| 输入 | 自动行为 | 手动覆盖 / 未知回退 |
| --- | --- | --- |
| 显示器与实际分辨率 | 默认当前窗口所在活动输出，失败时主屏；记录用于推荐的目标像素 | 可选屏幕或填写正整数宽高；边界在后端验证，不能修改系统显示模式 |
| GPU 与输出关联 | 用可验证的适配器/输出身份匹配能力；无可靠匹配则显示未知 | 不按显卡名称子串推断性能；不把活动显示 GPU 当成解码 GPU |
| 供电与分辨率/能力 | 电池/节电默认省电；其他均衡；4K/未知 GPU 保守，不自动叠加高成本增强 | 高画质可手选，限制及理由明确；只有已有目标设备证据才增加自动高画质规则 |
| HDR 能力与系统状态 | 自动模式遵循目标 MPV/输出链能力，未知不强制 HDR | 明确不支持时拒绝开启；系统未开时引导设置并复查；保留用户意图和实际可应用状态 |
| 音轨/字幕语言 | 空列表表示遵循媒体默认轨道 | 标准化允许的语言代码、有序去重和长度上限；未知语言/无匹配时按 MPV 回退 |

分辨率并非画质评分：同为 4K，1080p 放大与 4K 原尺寸不同。v0.1.1 不做媒体内容分析，不承诺据 GPU 和屏幕自动得到“最优”画质或能耗。检测推荐必须在界面显示依据，不能只有名为“自动”的固定档位。

参数实施前，针对当前清单的固定 MPV 提交核对 HDR 输出/SDR 映射、alang/slang、默认/强制轨道行为及现有三档参数的交互。选项存在只是必要条件；参数值和输出结果须验证，不能直接照抄最新 master。若底层语义不能完整支持设计，先修正这一项的方案与说明，不能交付无效控件。

优先级继续是公共默认 → 平台约束 → 档位 → 字段覆盖 → 有效代际播放档位 → 用户附加配置；其中播放档位仅影响档位字段，HDR 策略和语言不应被三档切换顺带重置。界面区分 GUI 基线、有效全局档位以及可能的 user.conf 覆盖，不将生成值等同于播放器实测值。

## 打开配置目录与文件选择

通过窄权限的平台函数调用系统目录/媒体选择器和打开目录能力；不暴露任意 shell 或全文件写入接口。优先复用现有 Windows API 与依赖；确需小依赖时写明用途、锁定版本及许可材料，不预先添加插件。

“打开配置目录”仅接受当前目标派生的已验证配置目录，不接受 UI 任意命令。user.conf 可由用户手工创建；若产品提供创建模板，必须单独预览、create_new、不覆盖。生成的 mpv.conf 仍受管理，直接修改它会触发现有覆盖/启动保护；界面明确推荐编辑 user.conf，而非鼓励修改受管理产物。

## 系统集成和稳定启动入口

继续复用 --open 和 --save-playback 的现有 Rust 入口，不新增常驻服务或独立语言实现。当前代码引用 current_exe，单 EXE 被移动/删除会破坏关联及 Lua 保存，需要本版处理。

两种交付形式统一使用所选根 launcher/mpvkit.exe。组件/配置事务一并复制当前应用及八份许可资源，预览逐文件列出；先提交稳定入口和 Lua 上下文，再允许系统登记。这样单 EXE 被移动或删除后，播放和全局保存不依赖原文件。安装包自身安装/升级仍需隔离 Windows 验收。

只复制真实运行和分发所需文件；是否能仅复制 EXE、资源如何保留，先做最小实验，不由“测试版单 EXE 能打开”推断全部模式成立。所有新增文件必须进入归属清单与恢复计划；有未知同名文件则拒绝覆盖。复制 helper 时同步通过配置事务改写 Lua 上下文引用，保留代际规则。

阶段次序固定为：稳定入口文件与配置提交成功 → 登记预览 → 按原有注册表事务登记 → 读取实际值核验 → 标记引导完成。登记失败保留组件和入口，进入可重试状态；不能清空文件事务来假装整体成功。后续手动更新 helper 仅使用当前应用的明确本地版本与预览，文件占用则提示重试，不引入自更新服务。

登记状态新增“有效/未登记/被外部改变/入口缺失/待恢复”等语义，核对实际登记值与入口摘要；不以 associations.json 存在作为 Windows 已登记。默认应用状态独立，未读取或无法确认就显示未知/由系统管理，不更改 UserChoice。

可访问目录切换前先恢复和移除当前登记；旧路径不可访问时允许明确预览后仅更换活动指针，原文件/登记完全保留，后续登记仍须通过冲突保护。原盘接回后可选择原环境移除旧登记；旧环境及正在播放的旧进程不被搬走或强杀。卸载先移除自有登记，再清理自有且未修改的入口文件；用户文件、未知文件和备份保留，执行中的文件删除失败应明确保留。

## 平台步骤和组件分组

前端用稳定步骤 ID 识别状态，由平台能力决定 integration 是否有待做工作以及用户文案。v0.1.1 只提供 Windows 实现；Linux 后续核对 .desktop 应用入口、MimeType 声明、打开方式与默认应用选择，并确保 Exec 指向受管理启动契约。不能因为安装了系统 mpv 包就认为其入口会加载 MpvKit 配置，也不能更改其他包拥有的文件。未来包已经正确集成则省略步骤；不提前写 Linux adapter、跨发行版安装器或模拟成功结果。

组件分组是展示映射：player 对应 MPV 与必要运行依赖，extras 对应 uosc/thumbfast 及各自依赖。现有固定 ID、版本、哈希、下载和部署事务仍逐项处理；不更改为一个不透明“大包”。聚合状态由实际子项计算，优先显示失败/待恢复，其次执行中/待装，全部通过才显示就绪。折叠状态只属于 UI，不影响后端前置条件或事件消费；失败必须映射回具体组件。基础管理配置和 MpvKit Lua 不设计成可取消的插件。

## 应用设置、界面语言与主题数据

应用偏好记录放默认根 .mpvkit/app-settings.json，复用归属检查、锁和原子写；不随管理目标切换，不放入 MPV settings v2，也不进入安装代际或备份回滚。播放器恢复/移除不能重置界面语言和外观。

实际字段：schemaVersion=1、language（system/zh-Hans/en）、theme（system/light/dark）、accent（system/blue/teal/violet/orange）、background（旧 v1 兼容字段，接受 auto/solid，读取和保存均规范为 auto，不再作为用户选项）。目录归属由 .mpvkit/owner.json 校验。未知版本保留并解释；校验枚举，不储存任意 CSS、HTML 或远程翻译地址。无记录时采用默认值，只读启动不创建文件；用户修改时才保存。轻量 UI 偏好允许即时预览并保存，不套安装变更确认；保存成功后应用；保存失败保留原选择并提示失败，不假装重启后仍有效。该例外只涵盖应用偏好，不放宽安装、配置或系统集成预览要求。

“设置”页统一组织：语言、外观、关于。关于为只读信息：版本/构建、仓库链接、项目版权/许可证、第三方声明、必要运行环境和开发版验收状态。版本来自构建元数据，许可来自现有资源；不复制一套可能失真的正文。2026-10-21 本机 git remote 未返回仓库 URL，后续从已确认的发布元数据补齐；不得凭目录名猜 GitHub 所有者或伪造仓库链接。外部链接由用户点击后打开已配置的 HTTPS 地址，不自动联网检查版本，也不把原始服务器错误当作产品文案。

### 语言匹配和文案接口

- Windows 平台读取用户首选 UI 语言有序列表；不要用时区、国家地区、用户名推断。浏览器示例可用 navigator.languages 作为模拟/后备来源，不能冒称 Windows 已核实。
- 手动选择优先；system 模式依次匹配可用语言。zh-Hans/zh-CN/zh-SG 映射简体中文，未带脚本地区的 zh 按本版约定回退简体中文；en 及 en-* 映射英文。zh-Hant/zh-TW/zh-HK/zh-MO 不误称已支持繁体，继续找列表中已支持语言；全无匹配回退英文，始终提供手选简体中文。
- 启动及重新激活设置页时复核系统语言；支持的系统通知到来时刷新。只影响 system 模式，手选不被覆盖。第一次显示主要内容前确定语言与主题，避免先闪出另一套语言/配色；读取失败使用可恢复默认值。
- 最小接口为两份同键的 zh-Hans/en 资源、类型约束的键查找和具名参数；复用 React 与标准 Intl 的数字、日期、数量格式，不为两个语言引入远程资源、翻译服务或通用本地化框架。出现真实复杂复数/更多语种需求时再评估成熟库，不自写完整 ICU 解析器。
- 完整句子作为资源，不拼接“已＋动作＋组件”。两套资源包含标题、按钮、空状态、错误、对话框、辅助技术标签、下载阶段及计数的正确英文单复数；以编译或检查入口确认键和占位符一致。缺键开发期报错，生产用安全回退文案，不显示裸资源键。
- Rust 对前端返回稳定错误 code/phase 与受控参数；UI 映射本地化短消息。无法识别的错误显示通用失败＋错误代码入口；原始堆栈/路径和后端当前中文 message 不直接作为日常提示。原生后端弹窗和 CLI 的用户可见错误也列入文案清单，结构化日志代码保持稳定。
- 文案插值按普通文本转义，不允许参数注入 HTML。切换语言不清空输入、不重新构造预览、不重启下载；同一个 operation ID 的结果用当前语言展示。OS 文件选择器跟随系统语言；MPV/uosc 自身翻译不自动纳入 GUI 双语承诺。

### 明暗与强调色

用现有 MantineProvider/createTheme、colorSchemeManager/defaultColorScheme 和固定版本公开 API。应用记录作为持久化来源，避免 localStorage 与 Rust 文件各保存一套不同偏好。用户的“跟随系统”意图与解析出的 light/dark 分开；监听系统主题变化，手选模式保持。原生窗口框、Mica 和 Mantine 表面使用同一解析结果。

强调色独立于明暗：默认读取系统强调色（取色不依赖系统是否给每个窗口标题栏着色），不可读时回退内置蓝色。预置少量经浅/深模式对比检查的 Mantine 配色，暂不做任意颜色编辑器。系统色只取一次受控颜色值并匹配已验证配色，避免直接把任意原始 RGB 当按钮背景；颜色来源和匹配规则留实现证据。高对比度优先 Windows 系统颜色和边界，暂时压过用户强调色，退出后恢复选择。

## 原生 Mica 接入边界

这是本轮新纳入的范围，替代此前“本版不做 Mica”。继续使用 Tauri/Win32 窗口，不引入 WinUI/XAML 或 Windows App SDK 运行时作为前提。

本轮已核对 @tauri-apps/api 的本地 2.12.4 声明：setEffects/clearEffects 及 Effect.Mica 已存在，要求透明窗口和兼容页面背景，Linux 不支持，前端调用需要额外 allow-set-effects 权限；Cargo.lock 已含 window-vibrancy 0.8.1。它证明可用接口存在，不证明当前程序已有材质或所有系统策略都被自动处理。

实施路径按简化原则选择：先复用锁定 Tauri Rust 窗口接口配置/清除原生效果，在平台模块内统一负责主题与回退；若直接使用前端 setEffects，只给主窗口所需权限，不开放通用窗口控制。没有真实缺口不再引入第二个材质库，不升级工具链。若固定实现无法正确处理某状态，补最小平台桥接或使用纯色，禁止未记录的私有 DWM 数字属性作为兼容承诺。

### 支持矩阵和层次

- Microsoft 的 Mica 设计面向 Windows 11；正式 DWM_SYSTEMBACKDROP_TYPE/DWMSBT_MAINWINDOW 路径下限为 build 22621。因此本版计划将 **Windows 11 22621+** 作为 Mica 首批验收基线；22000 等较早系统默认纯色，除非另有经验证且受支持的实现。材质下限不等于应用本体支持版本已经验收。
- 第一步先验证已锁定实现具体调用路径、透明 WebView2 是否正确露出底层、原生非客户区标题栏及阴影是否兼容。仅调用成功、设置 transparent=true 或看到主题色，不算 Mica 验证。
- 一扇主窗口仅设置一次标准 Mica。html/body/WebView2 与壳层避免实色覆盖底层；内容层按 Microsoft 分层指南使用适量低透明度中性色，控件/菜单保持对比；不要把整个应用 opacity 降低，也不让背景穿透成不可读。
- 默认保留原生标题栏和系统按钮；如需将内容延伸入标题栏，必须验证命中测试、拖动、双击最大化、Snap、Alt+Space、DPI 与可访问性。不承诺 web CSS 能代替原生标题栏集成，不因 Mica 把窗口交互改成自绘实现。

### 系统状态与降级

系统关闭透明效果、节电、高对比度、系统/图形环境不支持或应用效果失败时，按平台策略使用中性同主题纯色。高对比度使用系统背景，不能自行调淡；支持恢复时再重新评估。远程会话/低能力环境不强制开启，保留保守回退及原因。

Microsoft WinUI 控制器提供的系统策略行为不能直接假定 Tauri 也全做了：列清由 OS/库自动处理的项目，对缺失项目在平台层检测并响应相应变化。区分“原生调用可用”和“当前实际回退”；窗口背景始终自动决定，不持久化材质开关或一个永远为真的 micaEnabled。首帧、明暗切换、失焦/恢复和系统策略变化时不得露出透明孔洞或黑白闪屏；失败不阻止用户继续安装和播放。

不提供 Mica 色调、透明度、模糊半径滑块；应用强调色只作用于控件，不篡改材质的壁纸/主题行为。CSS blur、图片和浏览器模拟都不是材质验收证据；记录 Windows build、WebView2、DPI、系统透明/供电状态和实际降级结果，官方依据见[界面文档](ui-flow.md)。

## 实现补充（2026-10-21）

- 旧版健康环境无 setup.json 时只读识别完成；用户首次确认文件变更时，先记录已经验证的旧完成状态，再执行部署，避免 v1 转 v2 后退回初装。配置写入后如果进度确认失败，可再次确认，不重复下载。
- 综合报告带 externalMpv；重启与组件更新继续使用原外部播放器，不把未检测的外部版本标成固定下载版本。外部程序不纳入删除归属。
- HDR 开启使用 DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO_2 的 HDR 专用位与活动模式；旧系统/驱动拒绝该查询时返回未知，不从普通高级色彩推断 HDR。预览及文件执行前都检查目标输出，自动/关闭不切换系统设置。
- 原生外观通过平台 DWM API 设置并核验，使用原生窗口事件及每 15 秒策略复核。系统强调色匹配四个内置配色。Windows 11 22621+、透明启用、非节电/高对比/远程时使用 Mica；失焦/最小化保留配置，视觉由 DWM 管理。已取得本机前台明暗截图及 backdrop=2；跨设备、系统策略开关和多屏矩阵仍待补验。
- 应用版本取编译元数据；未配置仓库地址时直说尚未配置。关于页展示本地项目声明与第三方原文，不伪造链接。

### 目录选择简化

`target_status` 同时返回当前目标和平台默认根，前端不从自选路径推算默认位置。新安装无自定义勾选；已有自定义记录恢复勾选。路径未改变时只刷新检查，不申请目标变更计划。实际切换仍经过预览、重新核验和原子保存。`preview_target` 不接受布局开关，后端优先使用目标清单布局，其次保留同目标历史布局，否则采用 config 子目录；不根据 mpv.conf 的存在猜测归属。

### 启动材质修复（2026-10-21）

窗口配置 visible=false，Rust setup 在 show 之前调用平台 appearance 模块。直接使用既有 windows-sys 的 DWM API（增加 Win32_Graphics_Dwm 特性，未新增包），检查 HRESULT 并读回 DWMWA_SYSTEMBACKDROP_TYPE；不再用 Tauri set_effects 调度成功作为材质成功。Mica 配置不以瞬时焦点为门槛，原生 Focused/ThemeChanged 事件同步外观，15 秒复核系统透明/供电策略。事件只允许本地主管理窗口 listen/unlisten，不开放 emit 权限。

允许材质时恢复系统标题栏/文字颜色并延伸 DWM frame，客户区/WebView 使用透明背景；策略回退时使用同主题标题栏与客户区纯色，高对比度尊重系统颜色。旧 Windows 不支持自定义 caption color 时保留系统标题栏并记录 HRESULT。颜色属性仅支持设置，不能用 DwmGetWindowAttribute 读回；材质类型支持读回。返回 true 仅表示 DWM 接受并报告 MAINWINDOW，不承诺系统策略下每一帧都有可见壁纸色调。
