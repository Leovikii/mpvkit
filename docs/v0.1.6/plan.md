# v0.1.6 方案：预编辑与安装解耦

2026-10-22。**用户已批准产品实现与完整本地测试，源码和测试 EXE 更新为 v0.1.6。** 2026-10-25 用户授权提交并推送本批更新。继续遵守 AGENTS.md：无 CI/CD、开发版兼容/迁移和安装包。

## 设计决定

保留左侧两页：**播放器设置 / Player settings**、**应用设置 / App settings**。原播放器状态与组件安装并入播放器设置，删除独立管理页。应用设置仍固定在侧栏底部，保留语言、主题、强调色、关于和诊断。

用户已明确选择“预编辑”：首次未安装也允许修改草稿；可以把当前草稿随组件一并安装，也可以只安装组件，随后保存配置。**编辑草稿不要求组件存在；实际应用配置要求所有必需组件健康可用。** 不隐藏页面、不阻止查看或预览，不恢复引导步骤。

采用“保存配置”作为按钮名称；未安装时明确叫“安装并保存配置”，避免点击保存却意外下载组件。

## 页面布局

1. 页标题“播放器设置”。
2. 紧凑状态行：组件是否就绪、配置是否保存或 mpv.conf 实际修改时间。缺少组件时提供次要动作“仅安装组件”；损坏时为“仅修复组件”。组件版本和维护操作折叠。
3. 画质与 HDR 两行直接编辑。画质仅带一句建议，HDR 默认自动；不加硬件检测或默认行为介绍。
4. 高级选项默认折叠：系统打开方式意图、安装/配置目录入口（左侧标题“打开安装目录 / 打开配置目录”、副标题实际路径，右侧按钮“打开”）、组件版本、刷新、更新/修复/卸载等。异常和手改冲突直接显露。现有播放结束/截图等低频项建议继续保留在高级区，原有默认值不变；独立预览仅展示代表性控件，不将预览的省略视为删除后端字段授权。
5. 页面最底部固定操作栏：左侧仅在有意义时显示“未保存/已保存”；右侧为“预览配置”和唯一主要动作。内容独立滚动，按钮不会被长内容挤到屏幕外；小窗按钮换行，不能遮住最后一项。

已有配置且草稿未改变时禁用保存；预览仍可用。更新组件不应自动重置配置。已就绪且缺少配置时只保存配置，不重新下载组件。

用户补充确认：组件和配置均已安装后，仍在本页继续编辑；“保存配置”使用最新草稿预览并更新实际文件，不重复安装组件。主状态行明确显示 **mpv.conf · 上次修改**，文件预览中显示当前所选文件自己的上次修改时间。

正式产品时间取对应实际文件的 filesystem mtime，按界面语言和本地时区显示到秒；不使用 GUI 点击时间、草稿编辑时间或另存的应用时间戳。未保存/取消/写入前失败保留原时间；成功后重新读取真实文件时间，内容未变化的文件不重写、时间保持。例如只改 HDR 时，mpv.conf 更新，而 input.conf 和 thumbfast.conf 不应同步刷新时间。若失败恢复本身改动了文件，按恢复后的实际 mtime 显示，不伪造旧时间。进入页面、窗口聚焦、刷新及操作结束时重读，也能反映外部编辑；无法读取时显示“无法读取”，不把当前时间当作替代值。

## 两条路径

| 操作 | 组件阶段 | 配置阶段 |
| --- | --- | --- |
| 仅安装组件 | 确认固定资产、安装/校验 | 不生成或修改 mpv.conf/input.conf；草稿保留 |
| 安装并保存配置 | 使用固定组件集安装/修复，再校验全部就绪 | 使用本次确认的草稿，生成、备份并写入配置；按意图登记系统打开方式 |
| 保存配置 | 不重新安装；执行前重新检查健康 | 预览并应用当前草稿 |
| 修复并保存配置 | 按既有归属规则修复固定组件集 | 修复成功后应用确认过的草稿 |

“随组件一起安装配置”是一个用户动作串联两个现有业务操作，不宣称跨下载、文件事务和注册表的原子性。

草稿放在页面外的 React 状态中，切页和单独安装不清空；初版不为未保存草稿增加新文件。关闭程序前如果草稿未保存，使用 Mantine 确认弹窗提示放弃；不额外增加草稿自动保存或历史版本兼容。安装执行期间禁用影响本次计划的编辑；切应用设置不取消操作，顶部提供简短进度。

## 配置预览与执行边界

- “预览配置”仅查看，不下载、不写入、不登记。按文件选择展示完整待生成内容：mpv.conf、input.conf、script-opts/thumbfast.conf；已手改且将保留的文件明确标为保留，不能把默认模板冒充实际结果。来源/组件清单与系统登记摘要仍可展开。
- 主按钮也先打开同一预览，提供明确执行动作与取消。首次明确列出将安装的组件和配置；已有文件需同时提供差异、手改覆盖授权与备份说明。未勾选覆盖时阻止覆盖，不能只显示摘要绕过保护。
- **正式实施必须复用 Rust 配置生成/合并逻辑**，拆分“纯渲染预览”与“执行前组件健康校验”；前端不能成为第二套配置生成器。预览可以在组件缺失时返回候选文本，apply 必须要求组件就绪，测试此边界。
- 实施组合动作时，下载前确认固定来源/版本和用户草稿，安装完成后生成新的部署预览与目标文件摘要。本版保持一次最终配置确认，以呈现安装后真实登记与文件差异；文件被外部修改、组件能力变化或出现冲突时，停止并要求重新审阅。不能复用安装前已过期的部署 token，也不能默默扩大覆盖范围。
- 系统打开方式仅在核心、必需增强和配置均就绪后登记，不改默认应用。保持 Windows 平台边界，Linux 不预建空适配器；本版不实现 Linux 登记。

## 部分完成与失败

| 情况 | 页面表现 / 下一步 |
| --- | --- |
| 安装失败 | 直接提示“组件安装失败，配置未写入”；保留草稿，可重试安装，不显示配置已保存 |
| 组件已装好，配置保存失败 | 保留安装成果；提示保存失败，主按钮变为“保存配置”，只重试配置阶段 |
| 系统登记失败 | 配置已保存与登记失败分别呈现；允许重试登记，不重复写配置 |
| 核心或必需组件丢失 | 保留草稿，页面仍可编辑；禁用直接应用，主动作改为修复并保存 |
| 手改冲突 / 计划过期 | 显露冲突，要求查看新差异；现有文件保持不变 |
| 取消 / 程序退出 | 下载阶段沿用取消能力；提交文件期间不允许中断。已完成的组件安装可保留，不能伪报整套回滚 |

## 实施结构

- 复用 AppShell/NavLink、Paper、NativeSelect、Accordion、Modal 和现有过渡；固定底栏是 flex 布局，不增加路由、动画库、表单引擎或通用工作流。
- 前端合并页面，保留现有草稿、进度和状态来源；状态分清“组件就绪”“配置已保存”“登记成功”。
- commands 保持薄层；setup 负责明确串联，components/deploy/config/integration 仍各自负责安装、事务、配置和系统登记。
- 当前存储布局保持不变，不增加 user.conf、任务数据库、额外持久状态或历史兼容代码。必要事务恢复继续使用既有文件。
- 无默认硬件检测，保持当前 MPV 参数、语言优先级、最小快捷键、续播和字体。

## 预览及验收

入口和启动见 [preview/README.md](preview/README.md)。预览仅模拟状态和操作；配置示例使用固定资源 profiles.json/input.conf，并以示例路径展示完整文本，不是后端部署预览。正式程序仍需原生 IPC、失效计划、手改保护、恢复与隔离登记验证。

审阅重点：两页职责是否清晰、底栏位置、“仅安装组件”是否易发现、预览文件是否便于检查、失败后是否能理解哪些步骤已完成。测试包含两条安装路径、草稿保留、取消/焦点、双语/主题、正常/reduce 动效、640/900/1200 窗口与 200% 文本。

交接：产品实施、单 EXE 构建及必要本地验证已完成，证据及限制见 [evidence.md](evidence.md)。

实施细节：只读 `preview_configuration` 复用 Rust 合并器，返回三份完整文件及各自 mtime；保存使用输入摘要验证、重新生成的部署计划及所有保留文件的摘要守卫。组合安装顺序为配置/来源预览 → 获取并确认组件部署 → 最终配置与登记预览 → 保存。各阶段可取消，组件已安装而配置未保存时保留草稿和安装成果。组件更新沿用固定完整集合，不新增差分下载器；已有配置原样保留。
