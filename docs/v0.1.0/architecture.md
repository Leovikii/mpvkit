# v0.1.0 架构与数据约定

状态：设计基线与当前实现说明；M1已验收，M2–M5实现及隔离测试已覆盖主要能力，余下验收见台账。更新日期：2026-10-20。

## 设计目标

一个桌面管理应用、一套部署业务、一组受管理的 MPV 配置。首版支持 Windows，后续增加 Linux 平台模块。减少持续维护面，同时保证配置不会因覆盖、失败恢复或多实例写入而丢失。

## 已确定的架构决策

| 决策 | 理由与边界 |
| --- | --- |
| Tauri 2 + React + TypeScript + Rust | 沿用产品选型；UI 与本机操作分开 |
| 单一 Rust crate | 按功能拆模块即可；不建立多服务或大量 workspace crates |
| 独立 MPV 进程 | 复用成熟播放窗口、输入和 uosc；不引入 libmpv 嵌入成本 |
| 结构化设置生成配置 | 保留用户覆盖；不解析合并任意手写配置 |
| 默认用户级部署 | 常规安装和关联不要求管理员权限 |
| 静态、固定版本组件清单 | 首版不维护远程目录服务或任意依赖求解器 |
| 平台代码集中隔离 | Linux 接入时替换少量系统操作；不提前为单一实现建立 trait 层级 |
| MPV 原生能力优先 | 只在必要处增加 Lua，不复制播放器已有缩放和条件功能 |

## 模块与依赖方向

以下是建议结构，不要求在骨架阶段一次创建所有文件。达到实际复杂度时再拆分。

~~~text
src/                         React 页面、常用表单、薄 invoke 封装
src-tauri/src/
  commands.rs                参数验证、业务调用、进度事件
  detect.rs                  MPV 和设备信息汇总
  config.rs                  推荐、覆盖解析、配置生成
  components.rs              清单、获取、哈希与归档校验
  deploy.rs                  预览、执行、备份、恢复、卸载
  platform/
    mod.rs                   少量统一入口
    windows.rs               本地路径、Win32 检测、注册与系统设置
resources/
  catalog.json               固定版本组件清单
  profiles/                  经验证的配置
  scripts/                   少量 MpvKit Lua 脚本
~~~

依赖方向：React → Tauri commands → 业务模块 → 标准库/必要依赖及平台操作。

业务函数不依赖 React 或 Tauri 窗口对象；进度通过小型回调或事件数据传回。UI 不直接写文件、执行命令或访问注册表。配置生成与推荐尽量保持可直接测试的纯函数。

前端按用户要求使用Mantine 9.7.3组件库，React自身管理状态，保留原生form/fieldset语义。必须遵守下载的[官方LLM文档](../vendor/mantine/llms.txt)及[前端规范](frontend.md)；统一Provider/主题/样式顺序，不引入通用表单引擎或额外状态库。

## 平台边界

| 能力 | 公共部分 | Windows | Linux 下一版 |
| --- | --- | --- | --- |
| 路径 | 区分配置、状态、缓存、备份 | 用户本地应用数据路径 | XDG 路径 |
| 检测 | 统一结果和未知状态 | Win32 等受控本地查询 | 桌面环境及图形会话相关查询 |
| MPV 获取 | 已安装/外部所有权、版本能力 | 固定 Windows 构建部署 | 优先发现已有系统 MPV |
| 系统集成 | 操作预览和所有权记录 | 用户级注册、快捷方式、设置入口 | desktop 文件与 MIME |

用编译条件或平台模块导出同名函数即可；只有出现第二个真实实现且接口稳定时再考虑 trait。不要建立空 Linux 实现、包管理器插件框架或模拟完整桌面环境。

公共配置不包含 D3D11、Windows 专用字体、命名管道路径或平台 shell。首版建议的 D3D11 配置只能位于 Windows 部分，并由目标构建验证。

## 安装目录和启动契约

由平台 API 获取用户目录，禁止硬编码用户名。Windows 默认根目录可使用 LocalAppData 下的 MpvKit；M1 固定具体布局及 Tauri 应用标识。

建议按用途分开：

~~~text
MpvKit/
  runtime/                   自有 MPV 与运行依赖
  config/                    管理配置、scripts、script-opts、shaders
  state/                     GUI 设置、播放偏好、安装记录
  backups/                   可恢复的旧版本及文件
  cache/                     下载与暂存，允许重新生成
  logs/                      有界日志
~~~

版本化子目录可用于暂存或替换，首版只需保留上一成功版本和未完成操作所需备份，不建设内容寻址存储。

所有受管理的启动入口必须显式使用选定 MPV 与配置目录。通过 MPV 的配置目录选项建立独立环境，并验证实际加载行为、路径引用和脚本加载。不要假设外部 MPV 自带的 portable_config 或系统配置一定不会影响结果。

默认安装可以直接使用受控命令行启动 MPV；文件关联也必须遵守相同契约。若运行时路径随更新变化，可更新自有注册信息或提供轻量启动入口，M1 选择一种即可。启动入口不是常驻服务。

用户直接执行外部 mpv.exe 时可能加载其原有配置，UI 要说明。默认关联不能指向一个绕过 MpvKit 配置的命令。

### M1 启动切片历史（当前行为见文末 M2–M5 补充）

- 应用标识固定为 `io.github.mpvkit`；M4 将使用自有 ProgID `MpvKit.Media`，当前不注册。Windows 平台模块通过 `SHGetKnownFolderPath(FOLDERID_LocalAppData)` 获取用户级 `MpvKit` 根目录，使用 `KF_FLAG_DONT_VERIFY` 仅取路径，再走本地边界校验，不依赖用户名或环境变量拼接。
- 当前有三个业务命令：`discover_mpv` 只读查找候选；`preview_launch` 在阻塞工作线程查询版本与必要参数，保存一份内存预览；`launch_mpv` 消费对应 ID，并重新检查有效期（5 分钟）、程序和媒体长度/修改时间。发现业务和平台路径处理分别位于 detect.rs、platform/windows.rs，UI 只展示结果与用户选择。
- `discover_mpv` 仅检查四个固定 Known Folder 候选、程序同级候选和 PATH 前 64 项的 mpv.exe；空 PATH 不表示当前工作目录，不递归列目录。路径先经过本地/reparse 校验；不存在属正常未发现，其它不可用位置记录跳过原因并继续。ASCII 大小写重复候选合并位置标签，不据此认定来源或管理归属。发现不执行候选，也不写入文件或改变 UI 当前选择；版本查询仍由用户选定后的预览操作触发。
- 首次切片不生成播放配置；原生默认值通过 `--no-config` 隔离。显式 `--config-dir=<根>/cache/sessions/<ID>` 和 `--load-scripts=no` 随独立 argv 传入，`--` 后只有媒体路径。`--no-config` 优先于配置目录，不能声称已验证加载受管理配置；M2 再接入生成配置。
- 预览不写入；确认后只创建新会话目录，`session.json`（schemaVersion=1、owner、sessionId、mpvVersion）和 `session.log`。目录已存在即拒绝，不复用、不清理。日志不含媒体路径或查询输出，单会话最多三行；跨会话容量和清理尚未实现。
- 查询每次最多 3 秒，每条输出流最多 512 KiB，检查退出码。Windows 匿名管道先检查可读字节，避免等待继承管道的子进程；后台辅助进程不创建控制台窗口。播放进程不绑定 GUI 生命周期，返回进程号不等于验证播放成功。
- 本切片在访问文件前拒绝 UNC、设备路径、映射网络盘、相对路径、父目录和 reparse point。仅用于当前本地启动边界，不改变后续远程媒体的产品范围。M2 仍须针对部署落点补充锁、哈希、并发替换和恢复，不能拿当前长度/修改时间检查代替它们。
- 后续文件关联仍遵循同一显式配置 argv 契约；M4 实现时直接登记选定播放器及受管理配置路径，并随更新重写自有注册信息。当前尚无注册代码，资源管理器启动和 GUI 关闭后的真实播放待验证。

- 显式实机验收入口位于 launch/real_tests.rs，默认忽略，只有指定可信程序与已存在本地测试目录才运行。它复用生产业务函数；通用有界输出收集复用 capture_command，允许测试子进程局部设置环境。进程句柄的路径核对/存续/结束仅在 Windows 平台模块的 cfg(test) 中编译，不暴露应用命令。模拟回归不作为真实加载或播放证据，入口细节见 [验证要求](verification.md#m1-显式实机验收入口)。

## M2 事务核心历史（当前完整安装见文末补充）

部署核心位于 deploy.rs。默认根仍由平台 Known Folder API 提供；内部元数据使用根目录下 .mpvkit，通过 owner.json 核对归属，不能仅因目录名存在就接管。install.json、pending.json、previous.json 均为 schemaVersion=1；包括文件摘要、原件备份引用与摘要、外部 MPV、组件版本、变更前后状态及上一成功记录。先持久化 pending，再暂存和备份、逐文件应用、校验并写成功记录；失败或重启可按前后状态回滚。多文件状态不声称具有单一原子事务。

跨进程互斥采用 Rust 标准 File::try_lock；Windows 单文件替换集中在平台模块，使用 MoveFileExW replace/write-through。备份引用限制到已记录操作文件；卸载不递归删目录，未知文件、修改文件、外部播放器和备份保留。已修改管理文件阻止更新/移除；新的恢复冲突同样停止。当前尚无下载/解包或完整安装入口，维护页通过受控 deployment_status、preview_maintenance、apply_deployment 调用事务核心。

原生交互测试仅对调试构建设置 MPVKIT_TEST_MODE=1 与本地 MPVKIT_TEST_ROOT，WebView 数据同样隔离；发布构建忽略该覆盖。生产启动现将子进程 MPV_HOME 设为会话目录，防止缓存/状态沿用外部环境；配置参数契约不变。

## 数据约定

以下是逻辑模型，不是已经存在的 JSON Schema。首次实现时再固定字段名、序列化格式和最小样例，避免两套模型长期分歧。

| 数据 | 最低信息 | 写入者 |
| --- | --- | --- |
| EnvironmentSnapshot | OS/架构、显示器、GPU、电源、MPV 版本及能力、检测时间、未知原因 | 检测模块 |
| UserSettings | schemaVersion、安装目标、基础偏好、字段级用户覆盖 | Rust |
| PlaybackPreferences | schemaVersion、全局档位/增强选择、修订或更新时间 | 统一持久化路径，见下文 |
| ComponentCatalog | ID、版本/提交、平台、来源、资产、SHA-256、许可证、兼容范围 | 仓库维护者 |
| InstallManifest | 安装 ID、外部/自有归属、版本、部署文件及哈希、配置路径、系统变更与备份引用 | 部署模块 |
| OperationPlan | 操作 ID、目标、预计变更、执行前文件状态、下载与冲突 | 预览模块 |
| OperationJournal | 操作阶段、已完成步骤、恢复所需路径与结果 | 部署模块 |

不要存完整硬件型号评分数据库。检测字段缺失不等于 false；HDR 至少区分显示器能力、系统状态、当前播放输出可确认程度。

所有持久化结构有 schemaVersion。读取未知的新版本时保留文件并报兼容错误，不以默认值静默覆盖。已支持的旧格式进行显式迁移，迁移前保留备份。

## 配置生成与优先级

对 GUI 管理的设置，推荐计算顺序为：

公共默认 → 平台能力约束 → 用户选择的基础档位 → 字段级用户覆盖。

推荐只更新未覆盖字段。恢复推荐值意味着清除对应覆盖，不等同于重置所有设置。能力缺失时保留用户意图并解释无法应用的项，禁止悄悄把错误选项写入配置。

GUI 设置是来源，生成的 mpv.conf、input.conf 和 script-opts 是产物。用户自定义附加配置独立保存，保持原样；首版不理解其中所有 profile、include 或重复参数。

附加配置在启动配置中安排清楚的加载顺序，但不能承诺它永远具有最高优先级：播放时 Lua、条件 profiles 和用户命令仍可能修改选项。界面区分“计划值”和可确认的“实际值”，附加配置引起的冲突进入诊断。

已生成文件被手工修改时，部署前用哈希发现冲突，提供保留、导出/备份后重建或取消；不能直接覆盖。既有脚本可能被 MPV 自动加载，冲突检测不能只检查 mpv.conf。

## 播放期逻辑与持久化

uosc 菜单和键盘绑定调用同一个 Lua 入口。Lua 负责本实例状态、参数应用和菜单反馈；缩放阶段及可直接表达的条件优先交给 MPV。

每个档位定义完整的“受管理参数集合”。切换时恢复前一个档位留下的值，再应用目标方案；不能只追加 shader 或设置少量新值。下一媒体文件加载时重算本次状态，避免把上一文件的临时增强带入下一文件。

播放选择优先级：本文件临时选择 → 已保存的全局播放偏好 → GUI 基础默认。能力检查最后约束实际可用值；组件缺失时回退基础链，说明原因并保留可恢复的偏好。

“本次使用”默认只对当前媒体文件有效。“记为全局默认”立即持久化；不能只等正常退出。GUI 修改默认档位时要同步更新/清除对应播放覆盖，避免出现界面改了但总被旧值覆盖的情况。

GUI 不持续实时控制所有 MPV 实例。全局更新用于后续加载/启动；已经在播放的其他实例无需自动同步。需重启的参数与即时参数分开呈现。

持久化必须做到：

- GUI 与播放器不无保护地改写同一份 JSON；GUI 设置与播放偏好分文件。
- 多播放器实例写全局偏好时互斥、重新读取并只更新所属字段，原子替换最终文件。
- 写入失败保留本次播放选择，显示“未保存”，不能虚报全局保存成功。
- GUI 关闭时仍可保存；不要求常驻服务。

跨进程写入方案是 M4 的受限验证项：优先使用可靠的现有文件锁能力；如果 Lua 无法可靠完成，允许复用同一 Rust 程序的短时无界面子命令完成持久化。无需新服务或第二套存储系统。确定后把协议、超时、崩溃恢复与测试记录写回本节。原子重命名本身不解决并发丢失更新。

## 部署、恢复与取消

首版采用单安装目标串行变更，并以跨进程锁阻止第二个应用同时操作。锁占用时给出可理解信息。无需支持多安装并行。

阶段：计划 → 下载/校验 → 暂存 → 备份 → 应用 → 验证 → 完成；失败进入回滚或待恢复状态。

- 计划记录文件存在状态和哈希，执行前重新检查。用户改了配置就使计划失效，重新预览。
- 下载失败不触碰现有安装；解压及生成都先在暂存目录完成。
- 提交前写入恢复记录；修改多文件或注册表不假装具有单一原子事务。
- 播放器文件被占用时提示关闭并重试，不强杀进程、不覆盖部分文件后宣称成功。
- 取消在安全检查点执行。应用期间收到取消时完成当前不可中断步骤，再恢复或明确进入待恢复。
- 应用崩溃后，下次启动先检测未完成记录，提供继续恢复；完成恢复前不开始新变更。
- 回滚失败保留备份、日志和明确受影响列表，不能清除记录或标记成功。
- 验证通过后再更新成功安装记录；备份清理不得删除未完成操作所依赖的数据。

文件内容完整性采用同目录临时文件与可靠替换。涉及 Windows 文件锁、ACL、注册表的恢复在对应平台验证，不依赖 POSIX 假设。

## 文件归属与卸载

每个目标记录为新建、替换、外部或后来已修改。仅移除自有且未被用户修改的产物；替换文件恢复原件前，先确认当前文件没有新的用户修改。

外部 MPV 永不因 MpvKit 卸载被删除。截图、用户附加配置、未知文件和备份默认保留。彻底清理也只针对预览中列出的明确管理资产，不能递归删除一个可能混有用户文件的目录。

注册表操作使用独立应用标识，记录原值和写入值。卸载只删除仍指向本应用的注册信息；其他应用后来写入的值保持不动。不要修改 Windows 受保护的默认应用选择或声称能可靠恢复系统 UserChoice。

区分“移除受管理的 MPV 环境”和“MpvKit 自身安装包卸载”。自身卸载器不得绕过资产保护规则。

## 下载、命令与错误边界

- 资源使用固定 HTTPS 来源和版本；下载后核对清单中的 SHA-256。哈希保证与受信清单一致，不等同于独立证明发布者身份。
- 禁止浮动 main/latest 作为正式组件身份；不执行下载所得远程安装脚本。
- 拒绝归档中的绝对路径、父目录穿越及越界链接；检查展开规模。已有目标中的 junction/reparse point 也不能把写入或删除引向根目录外。
- 前端仅调用白名单业务 commands，校验参数和目标范围；不暴露任意 shell 或任意文件写入 API。
- 子进程参数使用独立 argv，处理 Unicode、空格、超时和异常退出。
- 业务错误至少包含稳定类别、用户可读说明、当前阶段、是否可重试及必要日志引用。敏感信息不直接拼进面向用户的错误。
- 进度区分下载字节与步骤完成状态；没有总量时显示不定进度，不编造整体百分比。

## 当前 M2–M5 实现补充（2026-10-20）

- components.rs 固定获取和安全解包在有上限内存中完成，网络失败不写安装；资源来源目录有明确 releaseReady=false 门槛。config.rs 以结构化设置生成受管理文件，resources/profiles.json 为三档共同参数集合，切换不会残留旧档参数。
- 受管理启动先核对清单/各文件/附加配置摘要，预览后变化拒绝执行；加载管理配置→有效代际全局档位→可选 user.conf，子进程 MPV_HOME 指向新会话。手动外部 no-config 启动仍可用。
- 播放偏好存于 .mpvkit/playback.json（schemaVersion/owner/revision/generation/profile），不作为安装清单文件；Lua调用同一exe的 --save-playback 短时入口，复用部署跨进程锁和原子替换，修订不符拒绝覆盖；GUI设置部署产生新代际。
- integration.rs 持久化逐值前/后及所有权，平台 registry.rs 只允许当前用户固定自有键和值名；.mpvkit/association-pending.json 用于恢复，外部修改保留。测试模式使用文件隔离后端，发布构建忽略测试覆盖。关联稳定入口为 --open，调用同一受管理启动业务。
- 诊断仅导出允许字段、固定版本和计数，不含路径/媒体/URL/原始配置/原始日志；预览后 create_new，不能覆盖目标。日志清理验证会话归属和受控事件内容，核对前置哈希后仅移除旧 session.log，保留最近20份；最多1024份日志，目录扫描上限8192项。缓存/备份/归属/用户文件均保留。
- NSIS 为唯一用户级安装包；自卸载只删除自身，未移除的关联或中断关联会阻止自卸载。真实注册表、干净机及发布验收不以文件后端/编译成功替代。

## 指定目标及清理补充（2026-10-20）

默认根仍由Known Folder获取；.mpvkit/target.json保存明确选择的管理根和config/直接目录布局。targets.rs负责只读解析、预览、过期状态、跨进程选择锁及执行前目标核对。切换保留旧目录，当前关联或未完成操作未处理时拒绝离开。安装记录新增configDirectory，旧记录默认config布局；选定现有配置目录时直接部署到该目录，原件仍走既有事务备份/恢复，未知自动脚本阻止覆盖。

同一个--open和--check-uninstall短时CLI解析选定目标。UI其它区域在切换后刷新；旧目标预览拒绝执行。全局保存helper仍带明确根和代际，允许已在播放的旧环境保存自己的偏好，不向其它环境传播。

缺失的可选组件文件使播放预览明确禁用全部自动脚本，保留基础链；配置或播放器损坏及任意管理文件被修改继续阻止启动。组件安装可安全补齐不存在的文件，执行仍重查不存在状态。播放列表切换会清除仅本文件档位，并读取有效全局偏好或恢复启动基线。

部署开始在pending之后写入receipts归属收据，记录每个暂存/备份的预期摘要。cleanup.rs只预览摘要相符且不被原件/上一成功清单引用的旧资产；收据最后移除，待恢复时拒绝清理。旧版本无收据资产、未知/修改文件、会话缓存及空目录保留。清理按文件执行，有部分成功时如实停止；不会递归删除目录。

原生注册表验收额外使用Windows Offreg建立独立文件、显式设置该私有蜂巢访问描述符，再经RegLoadAppKey的进程私有句柄运行同一RegOpen/Create/Query/Set/Delete API。该入口仅cfg(test)编译，生产仍使用HKCU精确白名单，不把离线蜂巢等同资源管理器验收。

组件下载独立设置10秒连接、60秒读写停滞和单资产10分钟整体时限。通过reqwest异步builder的整体timeout转换为阻塞客户端，并保留外层60秒等待上限；持续低速响应不会无限延长，正常慢速下载也不在60秒时被截断。取消仍在分块边界检查，网络停滞最多等待60秒。回环慢流与停滞回归分别覆盖两项时限。目标外部MPV在下载/配置前检查完整受管理参数键；不支持项拒绝部署，手动no-config启动只要求基础隔离能力。参数名存在仍不能证明任意后端/参数值均兼容。

受管理启动通过子进程MPVKIT_GENERATION绑定预览中的安装代际；Lua保存使用该绑定，而非重新读取的新清单代际。GUI设置变更后，旧播放器保留本次参数但不能保存到新代际，需重新启动；短时Rust helper仍在锁内核对代际和修订。直接绕过MpvKit启动的脚本没有可信代际，不提供全局保存。

## M2补充：部分写入失败与首次归属重试

共享write_new只在本次create_new成功后处理写入/同步错误：关闭文件并尽力删除本次半成品；create_new失败不删除已有目标。首次控制目录由本调用创建、且owner.json失败时仅移除空目录；已有未知目录或非空目录保留，不能按名称接管。故障注入仅测试编译、线程局部；验证暂存/备份/提交/回滚及重试，见[证据](evidence/2026-10-20-partial-writes.md)。

## 查询前的运行文件保护

受管理启动和诊断共用mpv::managed_executable：先确认runtime/mpv.exe归属、核对已记录runtime文件摘要，再允许能力/版本查询。启动的原有全部文件完整性检查也在查询之前；诊断遇到运行文件缺失/变化或无归属时，只报告计数/静态错误代码、实际版本为空。外部播放器查询前保留本地路径/普通文件/mpv.exe名称校验。变更不会自动覆盖；[进程见证与原生回归](evidence/2026-10-20-runtime-probe-integrity.md)记录执行前阻止的实际证据。
