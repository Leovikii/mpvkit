## 使用方式

先完成当前里程碑的最小闭环，再进入依赖它的任务。状态取值：未开始、进行中、已完成、受阻。只有满足验收且有证据时才能标记完成；写完代码、成功编译或静态读过文档不代表播放功能已通过验收。

以下工作量只用于排序。此前 4–6 周是熟悉技术栈的单人全职粗估，不是工期承诺；M0 完成后重新评估。

## M0：先证明播放方案

1. 从 MPV 官方安装入口查找 Windows 构建候选，核实维护来源、构建选项、架构、可获取的固定资产和许可材料。
2. 选择一个构建基线，记录 MPV 版本/提交及可确认的依赖版本；不得只记录“最新版”。
3. 选择上游 uosc、thumbfast 固定版本，检查完整发布资产及辅助程序，不假设只复制 Lua 文件就足够。
4. 在明确隔离的本地目录建立最小配置；用户本轮要求自动测试，允许默认选用仓库 .local/v010-tests 或新建临时子目录，不再重复等待提供路径。不得修改真实全局 MPV 配置或文件关联。
5. 验证独立配置加载、三个基础档位候选、硬解路径、缩略图和 SDR/HDR 基本行为。
6. 建立来源和配置决策记录，留下失败现象与未测试条件。
7. 外部 shader 仅在内置基线成立后做小规模对比，不阻塞基线实验。

交付：固定候选清单、最小可复现配置、验证报告。未验证的参数不能直接变成产品推荐。

## M1：应用骨架和明确启动

1. 初始化 Tauri 2、React、TypeScript 和单 Rust crate；固定 Node、Rust 与包管理器版本，提交必要锁文件。
2. 建立最小概览页、受控 command、日志与业务错误结构。
3. 用 Windows 平台 API 获取本地用户路径；定义应用标识、目录布局和自有文件关联标识。
4. 支持手动指定 MPV，再添加常见本地位置检测。不递归扫描全部磁盘或网络盘。
5. 查询版本与能力，启动指定媒体并显式使用隔离配置；处理 Unicode 和空格参数。
6. 确定后续关联使用的稳定启动方式，确认管理界面可以关闭而 MPV 继续播放。
7. 添加 Windows CI 的最小构建、格式和测试入口；README 写入真实可执行命令。

交付：一个能发现并启动 MPV 的最小应用。此时不创建无实际代码的页面框架、适配器或数据库。

## M2：部署与恢复核心

1. 落实最小组件清单、设置、安装记录和操作记录结构及 schemaVersion。
2. 获取固定资源、校验哈希、限制安全解压；可取消下载，失败不改变现有安装。
3. 生成可预览计划，包含冲突、归属、执行前哈希与系统变更。
4. 按暂存、备份、应用、验证流程部署；实现单目标跨进程互斥。
5. 注入中断及文件占用，验证回滚与下次启动恢复。
6. 支持已有 MPV 的外部所有权，使用隔离配置；显式替换现有配置走同一预览和备份流程。
7. 只在部署成功后更新成功记录，保留上一成功版本。

交付：UI 可调用的完整安装/恢复闭环，真实目录的改写不得用于替代隔离测试。

## M3：推荐与界面

1. 检测 GPU、显示器和电源，按能力提供 HDR 信息及未知原因。
2. 实现公共默认、平台差异、档位和用户覆盖的解析；重新检测不覆盖用户编辑。
3. 生成受管理配置及独立用户附加配置入口，检测生成文件和脚本冲突。
4. 完成首次向导及概览、播放设置、组件、维护页面中的必要内容。
5. 部署 uosc/事件菜单及 thumbfast，验证配置加载和缩略图路径。
6. 明确即时项与下次启动项，显示推荐理由，提供恢复单项推荐值。
7. 对两类目标设备运行代表性媒体测试。

交付：普通用户能完成首次安装并理解推荐。不得按 GPU 品牌直接宣称最优画质或省电。

## M4：Windows 集成与播放期设置

1. 注册用户级“打开方式”，打开系统默认应用设置；不操作受保护的默认关联。
2. 验证资源管理器打开带空格/中文路径媒体时使用正确配置。
3. Lua 统一实现档位/增强切换，恢复旧方案参数，保证菜单与快捷键状态一致。
4. 实现本次选择和全局保存；验证播放列表切换、组件缺失和异常退出。
5. 用最小实验选择可靠跨进程持久化方式，落实 GUI 与多 MPV 实例互斥及失败反馈。
6. 验证 GUI 关闭后的播放、快捷键和保存行为。
7. 如收录外部 shader，补充来源记录、触发条件、后端及 HDR 测试；否则保持不收录状态。

交付：F07/F08 可在隔离 Windows 环境完成，不能以“文件写入成功”替代真实播放器验证。

## M5：维护与发布

1. 基于当前固定组件清单比较可用版本，并执行更新；更新失败可恢复。
2. 按清单与文件当前状态卸载，保护外部 MPV 和用户修改；关联只清理仍属于本应用的值。
3. 完成恢复 UI、诊断导出与日志容量管理。
4. 确定一种 Windows 用户级安装包形式，处理 WebView2 依赖，不同时维护多种打包格式。
5. 验证自身卸载与受管理播放器清理之间的边界。
6. 完成 [发布检查](verification.md)，整理来源、第三方声明、源码和构建说明。
7. 更新 README、版本说明与支持矩阵；按用户授权发布，不自动推送或创建发行版。
