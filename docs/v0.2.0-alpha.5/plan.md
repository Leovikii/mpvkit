## 1. Linux 窗口：先统一基底，再验证模糊

已确认的源码原因：`platform/linux_appearance.rs` 固定把客户区设为不透明的深色 `#202020` / 浅色 `#f3f3f3`，材质状态始终返回 false；标题栏另由 GTK/KWin 装饰控制。只让网页背景透明，不能同时保证桌面模糊和标题栏一致。Windows 已有 DWM Mica 与实色回退，本版保留。

建议采用以下顺序，验收条件始终是**标题栏与窗口外层基底连贯**，内部内容面和卡片仍保留正常层次：

1. 先在隔离根启动原生窗口，核实当前 GTK 客户端装饰/服务端装饰、GDK surface 与 WebView 透明链路；验证 KDE Wayland 的原生模糊协议是否能作用于同一窗口基底。Linux 使用 KWin 模糊与主题染色，不称为 Windows Mica，也不承诺视觉完全相同。
2. 优先复用现有 GTK 原生窗口能力。若现有装饰无法共享基底，Linux 改用同窗客户端标题栏，优先评估已有 GTK `HeaderBar`，标题、按钮遵循桌面布局；标题区与内容外层共用主题色/透明度。避免重复品牌标题和第二条应用标题栏。Windows 继续原生 DWM 标题栏。
3. 模糊只用于窗口底层，不给每张卡片加模糊。KWin 接入必须使用当前窗口对应的 Wayland surface，不使用 X11 属性、全局 KWin 规则、用户脚本、系统主题改写或外部强制模糊插件。CSS `backdrop-filter` 不能替代桌面合成器的模糊。
4. 协议不可用、模糊关闭、透明链路失败或可访问性要求实色时，标题栏和窗口基底**一起**回退为同一实色；不能留下透明窗体配实色标题栏。仅“发出模糊请求”不能证明效果启用；无法可靠确认能力或关闭状态时选实色。

实现前的小规模原生验证决定具体接入方式；若需要新增窄用途 Wayland 绑定，先核对维护状态、与 GDK 连接的兼容性和许可，记录用途及锁文件，不手写一套协议框架，不升级现有工具链。若 GTK HeaderBar 也不能满足一致基底，采用 Linux 专用的统一客户端标题区，并验证原生拖动/缩放、最大化、最小化、关闭和窗口菜单；不以割裂的原生标题栏作为最终回退。

外观随系统/浅色/深色切换，不增加用户材质开关。需实测深浅主题、失焦、最大化、平铺、多屏 DPI、模糊关闭与实色回退；静态截图和离线预览不算真实材质通过。

## 2. 导航与职责

建议改为三个顶层入口；应用设置仍在侧栏底部，无需引入路由库。

| 页面 | 内容 | 底部主要动作 |
| --- | --- | --- |
| 播放器管理 / Player management | MPV 核心、uosc、thumbfast、字幕字体的版本/状态，分别安装、修复、检查更新及更新；增强移除与核心卸载；目录/来源明细折叠 | 缺失时“一键安装”，损坏时“修复安装”；完整健康时“前往配置” |
| 配置管理 / Configuration | 画质、HDR、自动连播、播放结束行为、配置状态/实际修改时间、配置目录、恢复默认配置；保留手改差异预览 | 首次“安装配置”，之后“保存配置” |
| 应用设置 / App settings | 语言、主题、关于、应用更新、许可与诊断 | 沿用现有局部动作 |

播放器页各行保留独立普通按钮，包括 uosc、thumbfast、字幕字体，不把它们继续藏成只有只读状态的明细。健康当前版本没有重复安装按钮；更新仍需先检查后明确执行。默认应用入口留在 MPV 行，组件许可/来源收在明细。

**配置解锁条件为核心可用且本版必需组件完整健康，不要求已经安装配置。** 未达条件时配置导航置灰、不可激活，旁边/可访问描述说明“请先完成播放器安装”；若原本停留在配置页而依赖失效，表单和保存立即禁用，展示“前往播放器管理”。不能仅降低透明度而保留键盘编辑或 IPC 写入。后端继续独立验证依赖。

安装完成后先保留同窗结果，提供“前往配置”和“关闭”，不强制跳页。首次进入已解锁的配置页加载默认设置，由用户安装配置；以后读取已保存设置。切页保留草稿，刷新状态不覆盖草稿；组件移除或核心不可用不删除已保存配置。正常关闭仍提示放弃未保存修改，这不是配置写入的第二次确认。

本版已批准三页与依赖门禁，覆盖旧“两页、未安装可预编辑”要求。以后的配置项直接加入配置页，不建立通用表单引擎。

## 3. 一键安装与独立安装

一键安装的范围是**补齐缺失核心与必需组件、修复损坏项**；健康项跳过，已安装系统核心保留，不自动升级或卸载。已有更新由各行的更新操作处理，避免“一键安装”暗含升级。配置文件的首次安装、修改和保存全部归配置页，不夹在播放器安装里。

完整流程：

```text
点击一键安装
  → 同一弹窗准备：读取状态、准备组件、校验、生成核心与文件变更预览
  → 展示全部目标、包/组件、路径、必要依赖、覆盖差异
  → 用户点击一次“安装”
  → 缺核心则调用原生包管理器 → 复核核心 → 部署所选组件 → 检查结果
  → 原弹窗显示结果：[前往配置] [关闭]
```

- 点击入口直接准备，准备可以下载固定来源的组件到受控暂存区，不安装核心、不覆盖目标配置、不提权。核心预览与组件预览合并呈现，不能安装核心后再弹一次组件确认。
- 系统 UAC/Polkit 保留，由原生包管理器处理；它是系统权限授权，不是第二次应用确认。仍用 Windows 固定 WinGet 包 / Linux Pacman 与 pkexec，不刷新 Pacman 数据库或强杀提交中的事务。
- 当前组件准备强制要求核心已存在；需要拆出不依赖已安装核心的下载/载荷准备，先预览全部已知变更。核心安装后才做运行能力验证；版本能力不足则停止，不盲目部署组件。
- 执行前复核核心计划、原生路径、文件摘要、包状态与锁。核心安装后，只允许计划内的“缺失 → 已安装”变化；路径切换、额外依赖/目标变化、文件冲突或过期计划必须停止并重建预览。不得把首次确认扩张成对任意新变更的授权。
- 核心成功、组件失败时显示“MPV 已安装，组件未完成”，列清实际结果；不卸载核心做跨包管理器回滚。重试只准备剩余项，重新显示一次具体预览，不静默沿用失败前的授权。
- 每个组件独立安装/修复/更新使用同样的一次确认流程。组件缺核心时说明依赖并引导一键安装，独立组件按钮不暗中串接安装核心。

## 4. 配置与组件必须真正解耦

现有 `components::prepare_install` 不仅下载全部组件，还调用 `config::runtime_files` 并写入配置状态；仅移动 React 页面不能满足分离。本版需同步调整：

- 按已有固定组件 ID 选择载荷，只下载/部署本次所需内容。保留未选组件的文件、版本和归属记录；不能因单独安装 thumbfast 而删除 uosc。公共许可证材料按实际归属保留。
- 把用户配置（mpv.conf、input.conf、脚本选项、结构化设置）与组件载荷的写入职责划清。首次播放器安装不生成用户配置；桥接/helper 按实际运行职责归属，所需文件全部进入具体预览，不隐式落盘。
- 复用现有归属清单、文件事务、fingerprint、锁及当前失败恢复，不引入第二套安装数据库或长期后台服务。状态分别表达核心、各组件、配置，不能仅凭一个 generation 就声称全部已安装。
- 组件维护不得重写用户配置或抹掉手改；配置操作不下载、安装或升级组件。恢复默认配置仍在配置页，完整预览后一次确认。增强移除按现有归属/摘要规则处理，明确展示涉及的配置与保留内容。
- 对相互依赖的安装过程复用现有业务编排，commands 保持薄层；UI 只发起任务和呈现状态，不在多个弹窗之间拼接写入授权。

## 5. 弹窗与过程反馈建议

保留 alpha.4 已有 Mantine Modal、TaskProgress、Progress、Loader、Button 和 Alert，建议优化任务摘要与阶段表达，不另造进度控件或复杂向导。

| 阶段 | 反馈与操作 |
| --- | --- |
| 准备 | 入口点击后立即打开唯一 Modal；显示当前组件、真实下载百分比或短阶段，支持实际可取消的下载 |
| 待确认 | 一句影响摘要，已装/跳过项从简；将新增、修复、删除和手改冲突明确展示；明细可展开；仅“安装/更新/保存”和“取消” |
| 执行 | 固定进度区域和正常尺寸按钮；显示“安装 MPV / 安装 uosc / 写入配置”等后端已知阶段，当前项及已完成项可见；执行按钮禁用，防重复提交 |
| 完成 | 以复核后的结果为准；播放器安装提供“前往配置”，配置显示“配置已保存”；不再确认成功 |
| 失败 | 具体原因、已完成项和下一步留在本窗；技术详情折叠；“重新准备”重建预览，“关闭”保留草稿 |

已知总量才用独立进度条；WinGet/Pacman 没有可靠百分比时用 Loader。可以显示任务项序号，但不能把“完成 1/4 项”换算成 25% 总进度。下载 100% 之后转为校验/安装状态。不能通过解析本地化控制台输出伪造进度，也不在按钮背景显示进度。

待确认前没有写入目标；确认后不再弹应用确认。显式“预览配置”若保留，只展示只读差异，不形成“预览 → 确认预览 → 再确认保存”的链条；建议首次简化为底部一个“安装配置/保存配置”，点击直接进入可执行的具体差异预览。

短确认弹窗随内容高度，任务长明细独立滚动，底部状态和操作始终可见；保留焦点锁、Esc/取消的真实能力、完成后的回焦、可访问名称和阶段播报。任务期间切页/自动检查不能覆盖当前弹窗。

## 本轮实现

- 三页和双语状态已落地，独立组件动作与一键安装并存。未满足核心/组件健康条件时配置导航具备 aria-disabled、键盘跳过和点击守卫；当前配置页的控件也随依赖失效禁用。
- `components::prepare_selected` 仅准备所选固定资源；`deploy::prepare_update` 保留未选文件与原始摘要、组件版本，同时对预览时状态加守卫。配置/helper 只在配置安装/保存时生成，组件安装不会暗写设置。删除旧合并组件动作判定模块，离线预览直接渲染实际产品 App。
- `setup::InstallationPlan` 合并核心与组件预览，执行前验证位置/摘要/过期状态，持应用锁调用原生核心，再部署与复核组件。核心已落地后的失败报告部分成功，重试重新准备。Linux Pacman print 事务提供名称、版本、架构、摘要及依赖错误，执行前重新查询，未刷新数据库。
- Linux 使用 GTK HeaderBar 与标准 `ext_background_effect_v1`，借用 GDK 的实际连接和 surface；只为窗口底层请求模糊，能力丢失或高对比时一起实色。新增 Linux 限定的 gdkwayland-sys 0.18.2、wayland-client 0.31.15、wayland-protocols 0.32.13，未升级工具链；Arch 明确依赖 wayland。双平台依赖清单和协议 XML 版权许可已保留。
- 原生截图曾发现两个缺陷并修复：① `WebviewWindow::set_background_color` 同时清空 GTK 基底，现仅让 WebView 透明；② GTK HeaderBar 的背景独立绘制，现与客户区显式采用同一 RGBA，标题与系统按钮颜色同步。不能把早期协议探测当成视觉通过。
