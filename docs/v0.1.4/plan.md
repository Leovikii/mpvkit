# v0.1.4 三标签与固定目录：实施与交接

日期：2026-10-22。状态：**已实现并完成本轮必要本地验证，单 EXE 已构建，待用户实际试用反馈。**

用户已明确：取消引导/状态的区分，使用“播放器管理 / 播放器配置 / 设置”三类标签；取消安装与配置路径自定义和外部播放器查找；未安装核心不展示配置标签；管理页展示安装、版本、更新、健康及配置状态，未安装配置时跳转配置页生成并安装。本稿取代此前两步引导、自动安装推荐配置和保留外部播放器的建议。

持续遵守 [AGENTS.md](../../AGENTS.md)：无 CI/CD、无历史开发版兼容或迁移、无安装包，仅本地验证与单 EXE。Linux 本版只确定平台边界。

## 1. 页面与首次使用

不再有独立状态页、引导页、完成页或步骤编号，首次和再次使用采用同一套界面。默认打开“播放器管理”。

| 标签 | 职责 |
| --- | --- |
| 播放器管理 | 核心/组件安装、版本、更新与健康；配置状态摘要；系统打开方式；修复、恢复及卸载 |
| 播放器配置 | 核心安装后显示；自动检测、推荐与自定义、配置预览/首次安装/后续调整、恢复推荐配置、打开配置目录 |
| 设置 | 始终可访问的完整页；应用语言、主题/强调色、关于/仓库/版权、诊断与日志清理 |

未安装核心时只显示“播放器管理”“设置”；核心安装并校验可用后显示“播放器配置”，即使尚无 mpv.conf 也必须可以进入生成配置。组件扩展失败不应被误认为核心未安装。核心丢失/损坏则管理页展示修复，隐藏配置入口并停止配置写入；若当前正位于配置页，返回管理页并保留本次内存草稿、明确说明原因，不静默写入。

建议使用顶部横向标签，保留原生标题栏；不再同时保留六项侧栏导航或设置弹窗。短文案、页面内容区滚动、底部操作不遮挡错误。弹窗只用于变更确认、冲突等短操作，长许可内容在设置页内展开。采用 Mantine Tabs，键盘操作与焦点遵循官方组件，不自造标签控件。

切换标签不自动保存或丢弃配置草稿，不取消正在运行的下载；任务状态在管理标签提示，任务期间阻止并发写操作，仍允许查看设置和其他信息。已有设置保存策略保留，播放设置明确点“安装配置/保存更改”才写入。

~~~text
MpvKit
[ 播放器管理 ]   [ 播放器配置 ]   [ 设置 ]

播放器管理
  MPV 核心        已安装 · 当前版本 · 正常
                  更新：尚未检查                 [检查更新]
  ▸ 播放增强      界面 / 缩略图 / 字幕字体
  播放配置        未安装                         [生成配置]
  系统打开方式    等待配置
  ☑ 添加到系统打开方式
  安装位置        C:/…/MpvKit/player              [打开文件夹]
  ▸ 高级维护                                  [卸载播放器]
~~~

无核心时主操作为“安装播放器”；安装成功后停留管理页，突出“生成配置”，不强制跳页。配置页初次显示检测结果和推荐值，用户调整后点击“安装配置”，预览并确认；成功后提供“返回播放器管理”，不出现“引导完成”。

## 2. 管理页状态与操作

各项状态来自文件、归属、版本和实际登记，不以按钮点击记录推断。整体摘要由这些事实推导，不新增 completed/confirmed 一类引导完成状态。

| 对象 | 展示与规则 |
| --- | --- |
| MPV 核心 | 未安装 / 正常 / 缺失 / 被修改 / 需要恢复；显示实际受管理版本。无有效归属不运行未知 EXE 做版本探测 |
| 播放增强 | 默认折叠，uosc、thumbfast、字幕字体逐项展示版本及健康；有失败时摘要提示并可展开 |
| 可更新状态 | 尚未检查 / 已是当前支持版本 / 可更新至具体版本 / 检查失败；不把查询失败说成“最新” |
| 配置 | 未安装 / 已安装 / 已手动修改 / 需要修复；未安装显示“生成配置”，已安装显示“调整配置”，均打开同一个配置标签 |
| 系统打开方式 | 未启用 / 等待核心 / 等待配置 / 已启用 / 未完成 / 需要恢复或检查；不等同系统默认播放器 |
| 任务和维护 | 当前下载/部署阶段与重试操作就地展示；文件或登记待恢复优先处理，不允许继续覆盖 |

更新只针对本项目已固定来源、版本、摘要并支持的资产；不新增远程可写清单或通用更新服务。“已是当前支持版本”不声称是上游最新。固定清单无新候选时不提供虚假的更新按钮；正常组件更新不得顺带重装或重置用户配置。

本版继续采用标准组件组合，不增加任意脚本/配置包选择器。安装与修复逐项展示结果，采用既有安全部署事务；组件的必要内部文件不因名称类似配置而裁剪。

“播放器管理”的高级维护承载恢复、清理无引用资产、卸载。应用设置的诊断/日志归软件自身维护。无需第四个维护标签。

## 3. 配置生成、安装与修改时间

核心/组件安装和用户播放配置安装是两个明确操作：

1. 核心阶段部署 MPV、固定组件与必要依赖/入口，不自动生成用户播放 mpv.conf/input.conf，也不把上游附带的 fonts.conf 当成“配置已安装”。
2. 核心可用后，“生成配置”进入配置页。自动检测屏幕、GPU/供电与 HDR；推荐仍保守，失败显示未知并采用可解释的默认值。画质、HDR、轨道语言等可调整；高级项收纳截图/结束行为等既有选项。
3. 安装配置预览列出生成文件和已选系统集成操作；确认后写入 mpv.conf、input.conf、必要 script-opts 与结构化设置记录。生成器和已安装时的范围保护复用现有逻辑，不新增配置模板引擎。
4. 后续修改只更新 GUI 管理范围。默认音量、字号和续播无新增 GUI 开关；用户直接编辑配置。手改冲突展示差异，标记损坏拒绝猜测，恢复主配置需整文件预览和备份。
5. 配置就绪按必需文件集合、可读性及当前归属记录判断；不单凭 mpv.conf 存在判定可安全接管，也不因用户修改有效文本就称损坏。未管理文件或未知状态停止自动写入，列出冲突，不导入旧配置。
6. 若配置已存在但无有效管理记录，仅有“安装配置”意图不能覆盖未知文件；明确预览实际内容和覆盖范围，仍无法确认归属时保留原件并提示处理。这里保护未知文件，不实现旧开发版兼容。
7. 组件更新不自动创建缺失主配置；主配置缺失由配置页明确修复。无核心时不提供独立配置包安装功能。

**时间建议：显示“主配置修改时间”，读取当前 mpv.conf 的文件系统最后写入时间。** 不新增 JSON 时间戳，不使用“进入页面/点击保存/成功检测”的时间。这样 GUI 保存和手动编辑都能反映；恢复备份也显示恢复后的实际文件时间，而非宣称原始创建时间。

- 文件不存在显示“未安装”；时间无法读取显示“无法读取”，不得改用当前时间。
- 后端返回可序列化的时间点，前端按当前语言与本地时区展示；保留完整日期/时间，不只有模糊的“刚刚”。
- 这项只代表 mpv.conf，不代表所有脚本和组件。input.conf/script-opts 的手动变化由“已手动修改”等现有检查反馈；不为了一个时间指标递归扫描整个目录或加入文件监听服务。
- 页面进入、安装/保存/恢复完成、窗口重新获得焦点或“刷新状态”时重新读取；若文件发生并发变化，按实际重新检查结果处理，不能展示缓存成功状态。
- 文件时间可被复制工具保留或人工修改，只用于展示，不能替代摘要、归属与并发校验。

## 4. 默认路径与删除范围

Windows 通过 Known Folder API 获取 LocalAppData，路径由后端统一确定，前端只展示：

~~~text
%LOCALAPPDATA%/MpvKit/
├── mpvkit.json                # 软件语言/主题/强调色，无目标选择记录
├── .mpvkit/                   # 全局软件数据归属与必要写入锁
└── player/                    # 唯一受管理播放器根
    ├── mpv.exe
    ├── d3dcompiler_43.dll
    ├── portable_config/       # 唯一播放配置目录
    ├── licenses/
    └── .mpvkit/               # 组件/配置归属、设置、集成意图、恢复与 helper
~~~

保留管理页“安装位置 / 打开文件夹”和配置页“配置位置 / 打开配置文件夹”；应用数据位置可置于设置详情。目录尚未创建时按钮禁用并显示“安装后可打开”；打开目录不隐式创建文件。权限不足、磁盘满或默认目录不可用时明确提示重试，不自动换路径、不请求管理员权限作为兜底。

移除产品里的自定义安装目录、外部 MPV 输入/浏览、已知位置/PATH 查找、接管已有管理根、目标切换预览/IPC/状态、历史路径回退，以及仅为这些功能存在的测试。删除 targets 模块的目标选择职责和全局记录的 target 字段；无旧记录迁移或字段补全。保留必要的全局写入锁，不能因删除 selection_lock 而让应用偏好并发写入失去保护。

公开安装/配置/启动命令从平台函数派生唯一根，不允许前端传任意根或 EXE 来绕过固定目录。受管理 helper 同样校验固定环境，删除外部播放器启动分支；核心检测只检测固定根，不扫描其他目录。文件/媒体选择仍可用于打开视频、截图输出和诊断导出，这些不是“安装目录自定义”。

Debug 专用隔离根继续保留用于自动测试，必须显式启用且校验路径，Release 不接受这一覆写。它不是产品用户可见的路径选项；本机验证仍不得写开发者真实默认目录。

固定路径不意味着目录内容天然归 MpvKit 所有。已有未知/被修改文件、reparse point、预览后更改、其他程序登记继续按原有边界保护。已存在的旧自定义安装不搜索、不迁移、不删除。

## 5. 系统集成与跨阶段失败

管理页核心卡片下默认勾选“添加到系统打开方式”。用户意图与实际登记分离，关闭后更新组件不再次开启。登记指向已验证的受管理 helper，不指向裸 MPV，也不修改 Windows UserChoice。

**建议执行时机：核心及配置均就绪后登记。** 核心安装阶段保存意图，界面说明“安装配置后添加”，状态显示“等待配置”。这样“安装核心”和“安装配置”分开后，系统不会新增一个尚不能按所选配置工作的入口。首个配置安装预览包含具体登记变更，用户确认一次；已经有配置时修改复选框只预览登记/移除操作，无需重复安装。

- 文件计划与登记计划在确认前准备，登记原值、目标入口和范围必须具体可见；写入前重新校验。
- 配置文件提交成功并核验后，才执行已授权登记；文件失败不登记。两份事务各自备份与恢复，不伪装成跨文件/注册表原子操作。
- 配置成功而登记失败：保留播放器和配置，显示“配置已安装，添加到打开方式失败”，仅重试登记；也可明确关闭集成。部分登记或待恢复日志先恢复/清理，不直接忽略。
- 重启不自动执行上次失败的系统写入，实际状态在管理页提示；无引导完成条件，不因集成失败阻止查看或修改配置。
- 已登记后配置丢失：提示“配置需要修复”，受管理打开明确报错，不默默改用另一份配置。管理页“播放文件”只在核心/配置可用时启用；直接手动运行裸 mpv.exe 的上游行为不作为配置就绪承诺。
- 已登记而对方修改注册值：保留外部修改，显示检查/恢复操作，不自动覆盖。

## 6. 卸载与保留数据

“卸载播放器”放管理页高级维护，预览分别列出移除的组件/系统入口与保留的数据。推荐默认保留 mpv.conf、input.conf、fonts.conf、script-opts、watch_later 及未知用户文件；移除自身拥有且摘要匹配的核心、组件程序/脚本/字体和不再使用的 helper。被修改的组件需先处理冲突，不能强删。

先安全移除自身系统登记，再移除程序；登记失败或需要恢复时不删入口造成悬空关联。保留的配置继续有必要的所有权/设置记录，不删除整个 player 或 portable_config。卸载不是恢复上一事务，也不是清空所有数据；本版不额外增加“一键删除全部配置”。

无核心后管理页显示“核心未安装，配置已保留”，配置标签隐藏。将来在同一当前格式环境重装核心时保留配置并恢复对应状态，不重新生成覆盖；这是当前格式日常安装行为，不是历史开发版迁移。重装时可再次确认系统集成意图。卸载、恢复与再次安装的保留清单和预览需要对应测试后才算完成。

## 7. 模块边界与未来 Linux

| 模块 | 本版职责 |
| --- | --- |
| App / types / i18n | 三标签、状态/草稿与进度，去掉设置 Modal、旧导航和引导状态 |
| commands | 薄 IPC，固定根由后端派生，取消目标切换/查找外部 MPV 接口 |
| setup 或现有状态业务模块 | 汇总核心/组件/配置/登记状态，组织具体安装与登记阶段；删除引导步骤/confirmed/completed 逻辑，不建工作流框架 |
| components / deploy | 核心与标准组件获取、部署、更新、保留配置的卸载与恢复；不直接写系统登记 |
| config | 首次生成/安装、后续范围更新、配置健康与主配置时间；不负责下载核心或选择目标 |
| integration | 系统集成状态和操作入口，依赖必要健康检查，避免反向调用 setup 形成循环 |
| platform | 默认路径、系统目录打开、Windows 注册值/登记恢复；当前仅实现 Windows |
| launch / preferences helper | 固定根的受管理启动、菜单保存和并发保护；不再提供外部播放器路径能力 |

公共状态不暴露 Windows 注册表数据作为跨平台必需字段，具体 before/after 作为平台详情。未来 Linux 按 XDG 数据/配置位置及 desktop entry/MIME 规范实现固定位置和桌面集成；不应一律省略集成，也不默认接管系统已有 MPV。无桌面能力时显示不支持、基础管理仍可用。

本版不实现 Linux、空适配器或通用注册表抽象，不宣称支持 Linux 编译。平台独立性依靠少量具体函数/模块边界，等第二个平台真正开发时再决定共用范围。

已删除 integration.status_with 中“无 helper 时按 current_exe 判定旧登记”的回退，入口缺失即无效。删除目标/外部功能必须覆盖前后端、CLI、测试和文案，不只是隐藏按钮；不移除仍用于路径安全/媒体选择/故障恢复的公共能力。

## 8. 本地验证范围

复用既有本地测试，更新为固定环境，不新增 CI/CD/安装器测试或历史迁移测试：

- 无核心仅两个标签；核心成功后配置标签出现且可生成配置；核心损坏/卸载后入口与草稿处理正确，设置始终可访问。
- 管理页状态、版本和“当前支持版本”检查一致；时间读取真实 mtime，手动改主配置、恢复、缺文件、读取失败不会显示虚假时间。
- 核心安装不生成播放配置；首次配置安装预览、取消、检测未知/手动覆盖、手改冲突、后续保存与配置修复分别验证。
- 核心缺失时后端拒绝配置写入；安装/配置/启动不接受任意路径；无 PATH 扫描或外部接管，默认路径失败不会回退写别处。
- 意图开启/关闭、配置前待登记、配置成功而登记失败、仅重试登记、重启后无自动写入、外部修改、部分登记恢复。
- 更新组件不重置配置；卸载保留配置/续播和未知文件，登记失败不删入口；同格式重装和故障恢复不丢归属。
- 并发、多实例、过期预览、目录被替换/reparse point、文件占用仍受保护；Debug 隔离测试不碰真实用户数据。
- 双语、标签键盘导航/焦点、浅深主题、640×600、长路径、任务切标签与配置草稿；原 EXE 移动、GUI 关闭后固定 helper 启动/保存。
- 仅 --no-bundle 构建单 EXE。Linux 仅审阅边界，真实系统登记和设备缺口如实记录。

上述三标签、固定路径、配置独立安装、真实 mtime、配置就绪后登记和卸载保留策略已获用户整体批准，并在本轮实现。

## 9. 本轮实施

- App 改为 Mantine Tabs；保留原生标题栏和统一图标/Mica。移除旧引导、侧栏、完成状态和设置弹窗；许可在设置页展开。配置草稿驻留 App，核心失效时隐藏配置标签、返回管理并保留草稿。
- 删除 targets、detect 模块和对应 IPC、外部播放器/目标字段及路径分支。固定路径由 platform 派生；打开目录不创建文件。全局偏好复用 operation.lock，helper 保存也验证固定根。
- 组件部署与播放配置生成分开。核心阶段部署运行时和稳定 helper，保存集成意图；首次配置必须明确预览。修复组件不重写或补建缺失主配置，同格式重装保留配置。
- setup 汇总真实状态和 mtime，并用具体 ChangePlan 组织文件/登记两阶段操作。Windows 注册表记录、预览、回滚位于 platform/integration.rs；公共 integration 只暴露现有操作入口，无 Linux 空实现。
- 首次配置预览含登记原值和目标；变更前复核全部相关注册项（含不需要改写的值），部署后核对已授权文件摘要再登记。登记失败保留配置；无文件变化时采用实际保留的安装记录摘要，重试不会误报过期。
- 卸载先移除登记，后删归属组件；配置、续播、未知文件与必要记录保留。文件预览过期时在移除登记前停止，登记失败不删 helper。独立登记拒绝被修改的 helper。
- 状态计算移除不必要的重复全量检查；Debug 为 sha2 单独启用 opt-level=3，保留完整摘要验证。此前原生测试暴露重复校验延迟，优化后完整原生四组约两分钟完成；不是画质/功耗结论。
- 本版无新运行依赖。版本/锁文件、应用依赖来源摘要及 Mantine Tabs 官方快照已同步；固定 core/hooks 仍为 9.7.3。
