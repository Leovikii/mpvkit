## 菜单状态与文案

所有可判定的选择使用 uosc 公开菜单数据的 `active` 字段，由上游渲染激活样式。激活状态与鼠标/键盘当前焦点分别表示，不自行拼接勾号或给每行附“当前”。每次打开读取实际属性；菜单打开期间通过公开 `update-menu` 跟随相关属性变化，不抢焦点、不重置层级或滚动，不用定时轮询。

| 菜单 | 中文选项 | English |
| --- | --- | --- |
| 画质 / Quality | 节能 / 均衡 / 高画质 | Power saving / Balanced / High quality |
| HDR | 自动 / 开启 / 关闭 | Auto / On / Off |
| 倍速 / Speed | 0.5× / 0.75× / 1× / 1.25× / 1.5× / 2× | 同左 |
| 自动连播 / Autoplay | 开启 / 关闭 | On / Off |
| 播完后 / When finished | 退出 / 保留窗口 | Quit / Keep open |
| 列表循环 / Playlist loop | 开启 / 关闭 | On / Off |
| 单集循环 / File loop | 开启 / 关闭 | On / Off |

文案只显示安装时确定的一种语言，不附技术参数、教程、作用范围或重复状态摘要。画质不再设“保存为默认”，也不再给每行附“当前”“仅本次”；四项选择统一按下节保存，激活标记只表示当前实际生效值。

### 选择即保存

beta.3 的 HDR、自动连播和结束行为实际上只影响当前进程，画质则区分临时切换与显式保存；不能把这些历史行为写成已永久保存。rc.1 按本轮审核意见统一以下四项：**画质、HDR、自动连播、播完后**。

- 菜单选中后立即应用，并自动调用统一播放默认值保存模块，生成后续启动读取的原生配置；不再要求第二次“保存”，也不在每次选择后弹确认。切集不恢复旧画质；自动连播选择仍不重建当前队列，结束行为仍只在队列结束时生效。
- 结构化偏好记录四项选择，生成原生配置供下次启动读取；管理器仍只显示画质控件。管理器普通保存、修复及画质变更必须保留已保存的其余三项，不因 GUI 没有控件而重置；完整重新应用保留这四项已保存选择，恢复其余预设文件，不悄悄恢复首次默认。复用安装语言，不跟随菜单选择切换语言。
- 菜单是保存偏好的显式操作；仅打开菜单、外部命令修改属性或观测属性变化不触发写盘，不自动吸收任意手改。只更新对应偏好与必要配置，不覆盖无关默认区或未知内容。
- 复用归属、摘要、锁、安装代际/偏好修订及失败恢复；过期、手改冲突或保存失败不能强行覆盖。运行期切换成功但保存失败时保留当前生效值，并短提示“保存失败，下次启动不保留 / Save failed; change will not persist”；不能把当前激活标记当作已保存证明。原生应用失败不保存新值，必要时恢复本次改动。
- 多个 MPV 实例与管理器并行时继续检查过期状态，不能互相覆盖较新偏好；已运行的其他实例不自动热同步。播放期普通保存不抬升整套预设修订，不建立旧版迁移或两套持久化来源。

这覆盖 beta.3 的临时画质/单独保存及三项固定默认的后续保存策略；不改 beta.3 历史行为记录。音量、静音、倍速、随机、循环及媒体轨道/设备选择暂不接入自动保存，播放位置继续使用 MPV 原生按文件续播；激活标记不代表该项目一定跨启动保存。

### 播放默认值保存模块

本轮明确将“保存默认值”从画质菜单业务中独立出来，供上述四项共用；不保留画质专用保存实现再为其他项目各写一套。最终生效载体仍是 MPV 原生配置，自动写入由 MpvKit 负责。解耦的是菜单展示、运行期应用与默认值写入的职责，不新增程序、常驻进程、依赖或独立偏好数据库。

| 职责 | 边界 |
| --- | --- |
| uosc 菜单适配 | 仅负责短文案、层级、激活状态和选择事件；不处理文件路径、配置格式、归属或锁，不改上游 Lua |
| 自有 Lua 选择处理 | 以受控项目和值应用原生命令/profile；应用成功后自动请求保存，失败则不保存；共用 helper 调用、结果处理与失败提示，不把持久化写进每个菜单回调 |
| Rust 默认值保存 | 以现有 `preferences` 模块为基础提供统一业务入口；校验项目和值、读取结构化设置、只更新指定项，并调用现有配置生成/部署事务。helper 仅作参数与结果适配，管理器保存也复用同一设置模型和更新规则 |

首批受控更新如下；接口接受明确的项目及合法值，不接受任意 MPV 属性名、命令、文件名或配置文本：

| 项目 | 合法值 | 原生配置来源 |
| --- | --- | --- |
| 画质 | 节能 / 均衡 / 高画质 | 现有三套画质 profiles |
| HDR | 自动 / 开启 / 关闭 | 现有平台 HDR 配置生成函数 |
| 自动连播 | 开启 / 关闭 | `autocreate-playlist=filter/no` |
| 播完后 | 退出 / 保留窗口 | `keep-open=no/yes` |

保存契约：

- 每次提交一项变更，使用最新且通过修订/代际检查的结构化设置保留其余项；不从播放器进程抓取全部属性再覆盖默认值，不另建一份与管理器竞争的偏好记录。保存成功返回新修订，供后续请求使用。
- 同一播放器的保存请求顺序执行，连续切换不能因“正在保存”而静默丢失；无冲突时最终落盘值必须与最后一次选择一致。跨实例仍使用既有过期检查和文件锁，冲突明确失败，不自动覆盖较新设置或无限重试。
- 所选项与已保存默认值相同且无配置差异时不重复写盘；即使运行期已经激活，但上次保存失败，再次选中也必须允许重试。只有事务成功才认为保存成功，不能先更新偏好记录后忽略配置写入失败。
- 保存模块不依赖菜单标题、排序、语言或 uosc 内部状态。将来接入设置项时，只补充该项的类型/合法值、原生应用和配置映射及必要验证；helper 调用、冲突处理和事务写入继续共用。不为尚未接入的项目建设插件注册、规则 DSL 或任意配置解析器。

现有 `preferences`/helper 是重构起点，文件归属、路径边界、摘要、互斥及失败恢复继续由原有事务提供；这不是新建第二套文件写入系统。菜单侧只有明确的选择动作触发保存，观察属性仍只用于显示实际状态。

状态判定：

- **画质**：核对当前画质相关属性与三套实际 profiles；不以最后点击的档位冒充实际生效值。手改或外部命令造成不匹配时不标记任何预设，不自动纠正参数。
- **HDR**：完整核对当前平台 HDR profile 的关联选项；自动/开启/关闭往返不得遗留参数。不匹配任何一套时不误标。标记表达配置模式，不能作为显示器实际 HDR 输出的证明。
- **自动连播**：读取 `autocreate-playlist`。`no` 为关闭，`filter` 为本程序的开启模式；其他原生非关闭模式也如实判为开启，选择“开启”则设置回 `filter`，不重建当前队列。
- **播完后**：`keep-open=no` 标记退出，`yes/always` 标记保留窗口；选择保留仍设置 `yes`。这里指整个队列结束，不立即退出；循环优先级沿用 MPV。
- **倍速**：数值匹配现有六档，1 与 1.0 等价；其他值不强行标成最近档位。
- **循环**：两项独立控制，`no` 关闭、无限/有限有效循环为开启；选择开启设置 `inf`。不把两种循环改成互斥模式。

“随机”暂保留现有 uosc 原生命令及其 OSD 反馈。固定版随机状态由 uosc 内部维护，没有本批确认的公开读取接口；不读取内部对象、不通过记住点击次数伪造激活状态，也不擅自改成“打乱列表”的另一种语义。本版激活标记覆盖上表可核对的属性。

实现复用现有自有 Lua 与文本表，经 uosc 公开 `open-menu` / `update-menu` 交付菜单数据；上游文件原文字节不变。菜单结构保持单一来源，不复制两份完整菜单，不手写任意 input.conf 解析器或通用菜单 DSL。先做小范围菜单原型验证父子返回、刷新和鼠标/键盘一致性，再采用满足这些行为的最小结构。

## Lua 调查与已确认拆分（2026-11-04）

本节的拆分与精简方案已获用户同意，尚未实施或运行验证。当前产品只有一份自有 Lua 模板：[mpvkit.lua](../../resources/scripts/mpvkit.lua)，共 161 行；[runtime_files](../../src-tauri/src/config.rs)生成配置根下的 `scripts/mpvkit.lua`，替换安装语言文本及管理器 helper 绝对路径。它由 MPV 原生脚本加载机制执行，管理器不需要常驻。`scripts/uosc/` 和 `scripts/thumbfast.lua` 是固定上游组件，不计入自有 Lua；`linux_tests` 和原生测试临时注入的取证 Lua 不进入产品。

当前自有脚本职责：

| 功能 | 当前实现 | rc.1 已确认目标 |
| --- | --- | --- |
| 画质应用 | 读取原生 profile，切换前记录参数，失败恢复；维护最后选择的档位 | 保留必要的原生应用及失败处理；状态改为核对实际属性 |
| 画质菜单 | 经公开 `open-menu` 生成三档、当前/临时提示和单独保存项 | 收入统一状态菜单，删除单独保存项与重复提示 |
| 画质保存调用 | 读取归属/修订/代际，调用管理器 `--save-playback`，显示结果 | 改为四项共用的 Lua 调用入口；权威校验和事务继续集中 Rust，不在 Lua 重写保存系统 |
| 切集恢复画质 | `file-loaded` 恢复启动参数快照 | 按选择即保存方案删除，不再维护这份快照 |
| Linux 首次窗口修复 | Wayland 首次唯一落屏后，属性稳定 0.5 秒再复核并仅重算一次；干预或切集取消 | 保留行为，独立为 Linux 专用脚本，与菜单/偏好业务隔离 |
| 运行状态发布 | `user-data/mpvkit` 发布最后档位和保存中状态 | 当前仓库消费者只有测试；新菜单不据此判定真实激活。随测试改用实际属性/保存结果后再删除无消费者的缓存，避免保留两套状态来源 |

目前 HDR、自动连播、结束行为、倍速和循环由 [input.conf](../../resources/input.conf)直接调用原生命令；播放位置、同目录队列、字幕发现及语言偏好由 [原生配置生成](../../src-tauri/src/config.rs)实现，没有自写算法。信息由 MPV stats 提供，缩略图由 thumbfast 提供，控件渲染和命中由 uosc 提供；这些功能不应迁入自有 Lua。rc.1 为四项自动保存增加选择处理属于业务需求，不是改写上游控件。

只按两块独立职责拆分，不按每个设置项拆一份脚本：

- `scripts/mpvkit.lua`：保持现有消息目标，负责菜单、实际属性观察、受控选择应用和共用 helper 调用；画质/HDR/自动连播/播完后使用同一流程。菜单与保存调用在文件内用局部函数分开即可，不新增 Lua 模块加载框架。
- `scripts/mpvkit-window.lua`：仅 Linux 部署，容纳现有首次窗口修复；无需读取安装记录、偏好、菜单文案或 helper 路径，也不依赖另一个脚本的初始化成功。两脚本不通过共享可变状态或互相发送消息协作。

拆分的收益是隔离平台窗口修复与持续扩展的菜单业务，而非减少当前行数；现有 161 行本身不构成拆分理由。窗口修复有既有回归依据，不因“只用原生配置”的目标直接删除，也不在本次整理中改变时序。保存真正落盘仍留在现有 [preferences](../../src-tauri/src/preferences.rs)与配置事务内；Lua 只保留必要的预期版本信息、应用及调用反馈，不再复制完整配置/归属验证规则。

实施须同步脚本生成、具体预览、归属/摘要/修复/完整重新应用、卸载清单及测试引用；新脚本纳入同一事务，未知同名文件仍受覆盖保护。当前 `window-policy.lua` 按注释从大脚本截取策略，拆分后应直接加载独立文件，保留现有取消、音频先行和只执行一次检查；Linux 原生窗口回归及 Windows 不部署窗口脚本检查另做，不能继承旧结果。不为脚本拆分添加旧文件兼容层。

本轮只核对生成与调用链、仓库消费者和既有测试入口，未运行产品、窗口或安装测试；上述拆分及状态缓存清理已确认待实施，不修改现有部署文件。

## 已确认菜单顺序

按以下组的顺序排列，组间只用原生分隔线，不增加不可操作的说明标题：

| 位置 | 从上到下 | 理由 |
| --- | --- | --- |
| 顶部 | **画质、HDR、倍速、自动连播、播完后、播放模式** | 自定义播放选择集中在首屏；倍速放在常用设置之前半段 |
| 中部 | **播放列表、字幕、音轨、章节、视频轨、片源版本、流画质** | 保留媒体选择能力；“片源版本”对应媒体 edition，避免与软件版本混淆 |
| 下部 | **打开文件、音频设备、信息、文件位置、配置目录、控制台** | 打开/输出设备/诊断及目录低频操作靠下 |
| 最后 | **退出** | 与“播完后 → 退出”区分：本项立即退出 |

“播放模式”内依次为随机、列表循环、单集循环；循环的开启/关闭使用上表一致样式。原生字幕/音轨/章节等菜单继续使用上游筛选与激活逻辑。信息同时保留菜单入口、`i` 短显和 `Shift+i` 切换，适配窄窗及键盘；不因增加控件删除可达入口。

置顶六项，不把所有功能塞入“播放设置”再多点一层；打开文件下移是因为日常通过系统 MPV 打开媒体。其他既有低频入口只重排，不增删截图、删除媒体等功能。

## 播放控件

右侧新增一个无媒体类型条件的信息按钮，使用公开 `command` 配置和现有 `stats/display-stats-toggle`，提示“信息 / Info”；不另写信息面板。再次点击关闭，与快捷键行为一致。“常驻”指控件栏显示时不按视频/音频/轨道数量隐藏，不把信息面板默认展开，也不强制整条控件栏一直显示。

保留统一尺寸 44、margin 12、spacing 6、进度条独占底行及上游描边/背景。默认尺寸下信息应可见；极窄窗口仍服从上游布局与收缩，保留更多菜单的信息入口，不缩小命中区或加自绘溢出栏。

左侧仍按上一集 → 播放/暂停 → 下一集排列。**本版以 `has_playlist` 同时控制两侧按钮**：队列 0/1 项时只显示播放/暂停，2 项及以上显示三项；列表运行期增删后跟随更新。

固定 uosc 的公开条件可直接判断队列是否至少两项，不能直接比较当前位置与列表首尾。已确认本版在多项列表首项/末项仍保留两侧按钮，沿用原生导航与循环语义，不承诺分别隐藏无上一项/下一项的按钮。不为细分首尾判断新增布局状态 Lua、外部 button 管理或内部桥接；后续若另提逐方向隐藏，需重新确认公开原生能力，本版不实施。

## Windows 安装后启动

当前模板默认 `$PassiveMode=1`，跳过完成页；已有 `.onInstSuccess` 仅在 `/R` 时启动，因此普通双击安装成功后自动关闭但不打开程序。此为模板路径已核对的原因，尚未做 rc.1 安装实测。

目标行为：

- 普通用户级双击安装，包括手动重装/升级，文件安装成功后显示原生完成页并等待用户操作，不自动关闭或提前启动管理器。标题“安装完成 / Installation complete”，复选框“启动 MpvKit / Launch MpvKit”默认勾选，按钮“完成 / Finish”；按安装器当前语言显示，不拼接双语。
- 点击“完成”后关闭安装器；勾选时通过现有 `RunAsUser` 请求启动新安装的管理器一次，取消勾选则只关闭。只在该完成动作触发启动，不以管理员身份启动，不增加第二次确认、倒计时、说明段落或额外向导步骤。
- 安装取消、失败或未完成不启动；启动请求失败应可见地报告，不把安装成功描述为启动成功。
- 官方 updater 的 `/UPDATE /P /R` 继续由既有重启路径负责，不显示完成页、不等待额外点击，只启动一次并保留 `/ARGS`；不能叠加完成页启动导致双启动。
- `/S` 静默安装不显示完成页，也不因本需求自动打开 GUI；显式 `/R` 保留上游语义。卸载不启动管理器。
- 不设置登录自启，不更改默认播放器或自动打开媒体。Arch `pacman -U` 保持包管理语义，不从包安装脚本中启动桌面程序；应用内 Arch 更新仍按现有流程请求重启。

实施优先复用现有 NSIS 模板的原生完成页与运行复选框，调整普通安装的页面条件及成功收尾，不另建自定义确认窗口。继续固定用户安装目录、进度页、WebView2/文件占用检查与错误处理，普通安装仍直接进入进度页，不恢复欢迎、目录选择等前置向导；更新模板差异说明、摘要/材料及相关契约检查，不能因为是安装器变更省略来源核对。
